# ADR-0092: Картинка комнаты (2026-10-13)

**Статус: принято.** Дополняет docs/04 (комнаты) и системные сообщения `SystemMessage` (message.proto). Выходит в 3.3.0.

## Контекст
Владелец, 13.10: «запрос на картинку комнаты — вместо иконки на текстовой/голосовой комнате поставить картинку, как в Telegram, плюс сообщение в чат, что кто-то поменял картинку группы; это супер удобно, чтобы искать комнаты». У пространства картинка уже есть (`Workspace.icon_file_id`, `AvatarPicker`), у комнаты — только глиф по типу (`#`, динамик, замок, таймер).

## Решение
1. **Протокол.** `Room.icon_file_id` (string, пусто = глиф по типу, как сейчас) и `Room.icon_url` не нужен — клиент строит `/api/files/{id}` как для пространства. `UpdateRoomRequest.icon_file_id` (`optional string`, `""` — убрать). Право — то же, что на имя комнаты: `MANAGE_ROOM` в комнате (и создатель временной комнаты). Файл — изображение, загруженное вызывающим в это пространство тем же путём, что иконка пространства/приложения (та же серверная проверка `appIcon`-подобная: владелец файла, тип image, лимит размера). `ROOM_UPDATE` несёт новое поле; снапшоты READY — тоже.
2. **Системное сообщение.** При смене картинки сервер пишет в комнату `SystemMessage.room_icon = 6` — `RoomIconCard { file_id }` (`file_id` пусто = картинку убрали); автор — кто сменил. Клиент показывает строку «Анна изменила картинку комнаты» с миниатюрой 40 px (тап — лайтбокс), как у остальных системных строк (`SystemMessage`). Уведомлений и звука у неё нет; превью в списке комнат — «изменила картинку комнаты».
3. **Где показывается.** Везде, где сейчас глиф комнаты: строки списка комнат на десктопе и телефоне (44 px диск → картинка в круге), шапка комнаты (диск 32), результаты поиска и ⌘K, карточка приглашения/join, переключатель комнат в полосе звонка, карточки задач с комнатой — через один компонент `RoomIcon` (вынести из `PhoneRoomList.tsx`/`Sidebar.tsx` в `components/RoomIcon.tsx`): картинка или глиф, поверх — те же состояния (зелёный тон у живого голоса, замок приватной — маленький бейдж в углу, как точка присутствия у аватара).
4. **Настройки комнаты.** В разделе «Основное» настроек комнаты — поле «Картинка» с `AvatarPicker` (загрузка, кадрирование в квадрат, «Убрать»), как у пространства.

## Последствия
- Протокол: новое поле `Room`/`UpdateRoomRequest`, новый `oneof` в `SystemMessage` — обратно совместимо; по правилам — Opus и второе ревью. Миграция: `rooms.icon_file_id uuid NULL REFERENCES files`.
- Удаление файла (чистка, ADR-0011) обнуляет `icon_file_id` (`ON DELETE SET NULL`), клиент возвращается к глифу.
- Старые клиенты игнорируют поле и показывают глиф; системную строку неизвестного вида они пропускают (как сейчас).

## Альтернативы
- **Эмодзи вместо картинки** (как у досок) — не решает «узнавать комнату по фото/логотипу проекта»; можно добавить позже тем же полем (`icon` строкой) — не делаем сейчас.
- **Системные сообщения и о переименовании** — Telegram так делает; в этом ADR только картинка, переименование — отдельным решением, если попросят.
