# ADR-0140. Телефон: ссылки на задачи и приглашения открывают приложение

Статус: принято для реализации (2026-10-28, DEV-4947). Дополняет [ADR-0067](0067-phone-shared-web-host.md)
и [ADR-0069](0069-phone-session-activity.md).

## Контекст

Ссылку `https://app.calab.io/t/INV-820` присылают в Telegram, а телефон открывает браузер, хотя
Calab установлен: оболочка `apps/mobile` не объявляла ни схему, ни associated domains / app links и
не читала входящий URL (`Linking`).

## Решение

1. **Какие ссылки.** Только задача `/t/<KEY>`, приглашение `/join/<code>` и ссылка комнаты
   `/r/<code>` — по тому же правилу кода, что `takeDeepLink` веба (`[A-Za-z0-9_-]{4,64}`,
   необязательный `/` в конце, query и fragment отбрасываются). Остальные пути этих хостов
   остаются в браузере. Схема `calab://t|join|r/<code>` (и старая `calaba://`, как у десктопа) —
   внутренний механизм, в шаринге по-прежнему только https (docs/09 #53).
2. **Нативная конфигурация** (`app.config.ts`): `scheme: ['calab', 'calaba']`; iOS
   `associatedDomains: applinks:<host>`; Android — intent filter `autoVerify` (VIEW, BROWSABLE +
   DEFAULT, https, каждый хост × `pathPrefix` `/t/`, `/join/`, `/r/`), фильтр схемы без проверки
   Expo создаёт из `scheme`. Хосты — только из env: `EXPO_PUBLIC_CALAB_LINK_HOSTS` (через пробел),
   по умолчанию хост `EXPO_PUBLIC_CALAB_URL`. Префикс `EXPO_PUBLIC_` нужен, потому что тот же список
   проверяет и бандл (Expo встраивает в JS только такие переменные); хосты не секретны, они и так
   в entitlements. `parseLinkHosts` (`src/config.js`) принимает только голые hostname в нижнем
   регистре и роняет сборку на мусоре.
3. **`/.well-known`.** `apple-app-site-association` и `assetlinks.json` отдаёт Caddy, значения
   (Team ID + bundle ID, package + SHA-256 сертификата) — из env; это отдельная ветка. Без них iOS
   не свяжет домен, а Android покажет выбор приложения вместо прямого открытия.
4. **Разбор входящего URL** (`src/links.ts`, `appUrlForLink`): одно строгое регулярное выражение,
   не `URL` — URL React Native приближённый (regex) и расходится с WHATWG на `@`, портах и
   обратных слешах. https принимается только с хоста из списка, без порта и учётных данных.
   Результат — всегда `${origin}/<kind>/<code>` собственного origin оболочки, а не исходный хост.
5. **Доставка.** Холодный старт: `Linking.getInitialURL()` читается до монтирования WebView, и
   страница грузится один раз сразу с маршрута — веб сам читает `location.pathname`
   (`takeDeepLink`), вошедший пользователь попадает прямо в задачу. Тёплое приложение
   (`Linking` событие `url`): если страница загружена, канал хоста включён и handshake ADR-0069
   пройден — событие host→web `calab-host-link` `{v: 1, host, document, url}`; страница
   открывает маршрут на месте, как клик по ссылке (`platform.app.onDeepLink` →
   `services/links.handleDeepLink`), без перезагрузки — идущий звонок не рвётся. Иначе (идёт
   загрузка, экран ошибки, канал выключен — сейчас весь Android, handshake ещё не было) WebView
   перемонтируется на URL маршрута; повтор того же URL во время загрузки игнорируется.
6. **Почему событие не добавляет полномочий.** Ack `calab-host-activity-ready` объявляет
   `links: 1`; веб принимает событие только после этого ack, от текущих host/document (как
   `calab-host-notifications`), ровно с четырьмя полями и только `url === location.origin` +
   канонический маршрут из п. 1. Это переход, который страница могла сделать сама; нативных
   возможностей, токенов и чужих origin в нём нет. Отзыв/logout меняет document — старое
   событие отбрасывается.

## Последствия и ворота проверки

- Сборка iOS с origin теперь просит entitlement Associated Domains: профиль подписи должен его
  включать (автоподпись добавит capability команде).
- На Android без канала тёплая ссылка перезагружает страницу (и рвёт звонок) до появления
  нативной границы канала (ADR-0069).
- Старый бинарник с новым вебом ничего не меняет; новый бинарник со старым вебом теряет тёплую
  ссылку (событие некому слушать) — веб выкатывается раньше.
- Unit-тесты и prebuild не доказывают работу на устройстве: нужен прогон «ссылка из Telegram»
  холодно/тепло на iPhone и Android после выкладки `/.well-known`.
