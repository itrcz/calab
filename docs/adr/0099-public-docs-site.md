# ADR-0099: Публичная документация на сайте — боты как интеграционный API, OAuth 2, SSO/AD (2026-10-14)

## Контекст
Владелец, 14.10: «нужна нормальная страница с документацией на примере GitBook: что есть у ботов и что пользователь может использовать API ботов как интеграционный API с площадкой; отдельно — как устроен OAuth 2 и как интегрироваться; отдельно — AD и SSO. Чётко структурировано, понятно и красиво; docs-раздел на сайте».

Что есть: лендинг `apps/landing` — Next.js 15 `output: 'export'`, Tailwind v4, 4 локали (`ru` источник, `en`, `es`, `zh`), юридические страницы из JSON с оглавлением и якорями (`[locale]/legal/[document]`), CSP `default-src 'self'` (никаких внешних скриптов/шрифтов), тёмная тема; markdown-пайплайна нет. Справочник Bot API — `docs/19-bot-api.md`/`.en.md` (REST-группы, gateway, команды, вебхуки). OAuth 2/OIDC-провайдер — `internal/oauthprovider` (per-workspace issuer, code+PKCE, refresh, userinfo, revoke; клиенты в настройках пространства; Business+). SSO — только OIDC (generic, Entra, AD FS), режимы off/optional/enforced, recovery kit; каталог — LDAPS read-only, синк 5 мин, fail-closed через 1 ч. Полный список маршрутов для ботов — `apps/server/internal/app/botroutes.go` (`botAllow`/`botDeny`/`botPublic`, тест на полноту).

## Решение

### 1. Где и как
- Раздел `/{locale}/docs/…` внутри лендинга (тот же домен `LANDING_HOST`, тот же билд `pnpm -F @calaba/landing build`, Caddy без изменений: `try_files … {path}/index.html`).
- Контент — Markdown в репозитории: `apps/landing/src/content/docs/{ru,en}/<section>/<page>.md` с frontmatter `title`, `description`, опционально `order`. Навигация — один файл `apps/landing/src/content/docs/nav.ts` (секции → страницы по slug, подписи на двух языках); страница без файла в локали → показывается `en` с плашкой «пока только по-английски». `es`/`zh` → `/en/docs/…` (как у юридических).
- Рендер на этапе сборки: `unified` (`remark-parse`, `remark-gfm`, `remark-rehype`, `rehype-slug`, `rehype-autolink-headings`, `rehype-stringify`) + `shiki` для подсветки (инлайн-стили при сборке — совместимо с CSP). Никакого рантайм-markdown.
- Расширения разметки (минимум, GitHub-совместимо): callouts `> [!NOTE] / [!TIP] / [!WARNING] / [!DANGER]`; вкладки кода — подряд идущие блоки с мета `tab="curl"`, `tab="JavaScript"`, `tab="Python"` объединяются в один переключатель; таблицы GFM; `<details>`; ссылки между страницами относительные (`../oauth/flow`), проверяются на сборке (битая ссылка = ошибка билда).
- Внешний вид (в духе GitBook, в токенах сайта): слева — боковая навигация с секциями и текущей страницей, сворачивается на телефоне в шторку; по центру — текст шириной ≤ 760 px, заголовки с якорями, «Предыдущая / Следующая» внизу, «Изменено: дата» из git; справа — оглавление страницы (h2/h3) с подсветкой текущего; сверху — поиск (клиентский, индекс JSON собирается при сборке: заголовки + первые 200 символов секций, без внешних сервисов), переключатель языка, ссылка «Редактировать на GitHub». Код: тёмные блоки с кнопкой «Копировать» и подписью языка. Темы — как у сайта (тёмная); если сайт получит светлую — через те же токены.
- SEO: `sitemap.ts` включает все страницы docs обеих локалей, `hreflang`, `llms.txt`/`llms-full.txt` собираются из того же контента (а не руками).

### 2. Структура
1. **Обзор** — что можно интегрировать (боты, OAuth 2, SSO/каталог), базовые URL (`APP_HOST`, `IDENTITY_PUBLIC_ORIGIN`), версии (`GET /api/version`, gateway `?v=1`), лимиты, где взять токены, поддержка.
2. **Боты и интеграционный API** — быстрый старт (создать бота, токен, первый запрос, первое сообщение); аутентификация; REST по группам (сообщения, комнаты, участники, доски/задачи/чек-листы/вехи, формы, календарь, DM, файлы, стикеры, поиск, Диск, Вики, профиль бота) — у каждой группы: что умеет, таблица маршрутов (генерируется из `botroutes.go` скриптом `tools/gen-bot-routes.ts` → `_routes.json`, страницы читают его), примеры `curl` / SDK; gateway (подключение, IDENTIFY/READY/RESUME, события с таблицей, SUBSCRIBE/TYPING/PRESENCE, коды закрытия); slash-команды и inline-кнопки; вебхуки (бот-вебхук с подписью, вебхук доски с `v1=`-подписью и событиями `task.*`); пересылка уведомлений о задачах боту (ADR-0090); SDK `@calaba/bot-sdk` (установка из репозитория, API, примеры из `examples/bots`); ошибки и лимиты; журнал изменений API.
3. **OAuth 2 / OIDC** — для чего (вход «через Calab» в сторонние сервисы, доступ к профилю); регистрация клиента (настройки пространства → OAuth, тариф Business+); issuer на пространство и discovery; поток Authorization Code + PKCE пошагово (с диаграммой последовательности в SVG); токены и сроки (access 5 мин, code 1 мин, refresh 8 ч/30 мин idle, ротация секрета 10 мин); `userinfo`, `refresh`, `revoke`; экран согласия и управление доступами пользователем; ошибки; чек-лист безопасности; чего нет (client_credentials, динамическая регистрация, introspection).
4. **SSO и каталог (AD)** — обзор и термины; режимы off/optional/enforced и что меняется для людей и гостей; подключение OIDC: generic, Microsoft Entra, AD FS 2019+ — пошагово со скриншотами настроек (QA-снимки экрана `identity`); recovery kit; каталог LDAPS: требования, фильтр групп, objectGUID, синк 5 мин и fail-closed через 1 ч, статусы объектов; повторная аутентификация (ADR-0055); для операторов — переменные `IDENTITY_*` (ссылка на развёртывание); диагностика типовых ошибок; чего нет (SAML, SCIM, JIT-создание).
5. **Справочник** — все маршруты ботов одной таблицей, таблица событий gateway (из proto enum), коды ошибок, лимиты, формат токенов, версия API.

Источник правды — код и proto; `docs/19-bot-api*.md` переезжает в раздел (в `docs/19` остаётся ссылка), чтобы не было двух копий. Тексты — `ru` и `en` одинакового объёма; термины — `docs/i18n-glossary.md`.

### 3. Проверки
- Билд лендинга падает на битой внутренней ссылке, отсутствующем переводе nav-подписи и расхождении `_routes.json` с `botroutes.go` (генератор запускается в билде, `git diff --exit-code` в CI `ts`).
- Визуально: страница docs на 1280 и iPhone 14 (светлая тема не нужна — сайт тёмный), QA-снимки один раз (новый интерфейс).

## Последствия
- Новые dev-зависимости лендинга (unified/remark/rehype/shiki) — только на сборке; размер клиентского JS не растёт, кроме поиска (≤ 10 КБ + индекс).
- `docs/08` — раздел «Сайт → Документация» с правилами разметки; `CHANGELOG` «Коротко»: «на сайте появилась документация для разработчиков».
- Контент про Диск/Вики для ботов — после задачи B1 (боты на Диске и Вики).

## Альтернативы
- **GitBook/Mintlify/Docusaurus отдельным хостом** — внешний сервис или второй сайт с другим дизайном и CSP; отклонено: одна сборка, одни токены.
- **Генерация REST-справочника из OpenAPI** — OpenAPI нет; источник маршрутов — `botroutes.go` + proto, этого хватает; OpenAPI — v2, если появится.
- **Только английский** — владелец и команда русскоязычные, сайт четырёхъязычный; делаем ru+en.
