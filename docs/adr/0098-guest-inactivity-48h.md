# ADR-0098: Гости уходят через 48 часов без возвращения (2026-10-14)

Уточняет [ADR-0016](0016-guest-access.md) (7 дней) и [ADR-0097](0097-former-members.md).

## Контекст
Владелец, 14.10: «гостей нужно удалять через 48 часов, если они повторно не заходили, а то список сбоку разрастается».

Сейчас: `GuestInactivity = 7 суток`, таймер сдвигается при каждом обновлении токена (`TouchGuest`); сметается раз в час (`guests.Cleanup`) только **гостевой аккаунт** (`users.is_guest`): файлы, членства, заметки, сессии, анонимизация «Гость (удалён)». Зарегистрированный пользователь, вошедший по ссылке с ролью «гость», не истекает никогда и остаётся в списке участников.

## Решение
1. **Срок — 48 часов без активности**, единый для обоих видов гостей: конфигурация `GUEST_INACTIVITY` (env, по умолчанию `48h`; `GuestSessionTTL` остаётся 24 ч). «Активность» — живое соединение шлюза или любой API-запрос: `workspace_members.last_active_at` у строк с ролью «гость» обновляется не чаще раза в 5 минут (как `TouchSession`), при подключении к шлюзу и при READY. Гость в звонке или с открытым приложением не истекает: сметание пропускает тех, у кого есть живое присутствие (Redis presence) — проверка под той же блокировкой, что и сейчас.
2. **Два уровня сметания** (тот же часовой `guests.Cleanup`):
   - **членство с ролью «гость»** у зарегистрированного пользователя, `last_active_at < now − 48h` → `removeMember` с reason `guest_expired`: событие `WORKSPACE_MEMBER_REMOVE`, строка в `workspace_former_members` (в списке бывших — под переключателем «гости»), файлы и сообщения остаются (это обычный аккаунт); сам может вернуться по новой ссылке;
   - **гостевой аккаунт** (`is_guest`) — как сейчас (файлы, членства, анонимизация), порог — те же 48 ч вместо 7 суток; бэкфилл `guest_expires_at` для существующих гостей: `min(текущее, now + 48h)`.
3. **Сайдбар**: в списке участников гости — отдельная сворачиваемая группа «Гости · N» (по умолчанию свёрнута, если гостей > 5), чтобы список не разрастался даже в 48-часовом окне; строка гостя показывает «был(а) 3 ч назад» вместо статуса.
4. Владелец пространства видит в Настройки → Участники → «Гости» подпись «Гости без активности удаляются через 48 ч» (не настройка; настройка по пространству — v2, если попросят).

## Последствия
- Миграция: `workspace_members.last_active_at timestamptz NULL` + частичный индекс по роли «гость»; изменение дефолта `GuestInactivity`; `docs/adr/0016` — ссылка сюда.
- Интеграционные тесты: истечение членства-гостя, пропуск активного (присутствие), повторный вход по ссылке, бэкфилл.
- Риск: гость, которого пригласили «на следующей неделе», исчезнет из списка — вернётся по той же ссылке (ссылка живёт по своим правилам ADR-0016).

## Альтернативы
- **Только сдвинуть константу 7 → 2 суток** — не решает зарегистрированных гостей и держит таймер на обновлении токена (открытое приложение без активности считалось бы активностью); отклонено.
- **Удалять по времени с момента приглашения** — выгоняет активных; отклонено.
