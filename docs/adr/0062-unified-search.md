# ADR-0062: Единый поиск — сообщения, задачи, события, файлы, заметки, расшифровки (2026-10-03)

**Статус: принято.** Миграция **00064** (00063 — поправка 1 ADR-0061). Уточняет docs/09 #3 (⌘K), ADR-0042 §3
(поиск задач, «trigram по ключу» — не был сделан), ADR-0039 (заметки), ADR-0025 (расшифровки), ADR-0038/0041/0045
(календарь и приватность событий), ADR-0059 (доступ по карточке).

## Контекст
Владелец (03.10): «в поиске нельзя найти задачи или эвенты из календаря — надо поиск улучшить». Сейчас ⌘K
(`features/shell/QuickSwitcher.tsx`) ищет комнаты, DM, полки заметок, участников (на клиенте) и сообщения активного
пространства (сервер, `SearchMessages`: `websearch_to_tsquery` russian+simple, `ORDER BY id DESC`). `GET
/workspaces/{id}/tasks/search` есть, но в ⌘K не подключён; событий, файлов, расшифровок в поиске нет; нет поиска по
началу слова («рел» → «релиз»), опечаток, подсветки, фильтров. Решения владельца: искать **всё** — сообщения, задачи и
их комментарии, события, файлы по имени, текст «Заметок», расшифровки встреч; по умолчанию — **активное пространство
и переключатель «Везде»** (все пространства + личные сообщения + заметки).

## Решение

### 1. Один эндпоинт, разделы
`GET /api/search?q=&scope=<workspace_id>|all&types=<csv>&limit=1..20&type=<one>&cursor=` → `SearchResponse { sections:
[SearchSection { type, items: [SearchHit], total_estimate, next_cursor }] }`.
- Без `type` — «сводка» для ⌘K: каждый запрошенный раздел, `limit` по умолчанию 4; с `type` — одна лента раздела с
  курсором (панель «Все результаты»), `limit` по умолчанию 20.
- `types`: `messages` (комнаты и DM), `task_comments`, `tasks`, `events`, `files`, `notes`, `transcripts`; по
  умолчанию все. `q` 1..200 символов; лимит частоты — как у текущего поиска (`SearchLimit`, на пользователя).
- `SearchHit` (oneof по типу): ссылка на объект (id сообщения + room_id, ключ задачи, id события + начало вхождения
  повтора, id файла + сообщение, id записи + смещение сегмента в мс), заголовок, `snippet` с подсветкой
  (`ts_headline`, маркеры `\u0002…\u0003`, клиент рендерит `<mark>` без HTML), `workspace_id` (для «Везде»), время,
  автор. Разделы считаются **параллельно** (errgroup), у каждого свой `SET LOCAL statement_timeout = '1500ms'`;
  раздел, упавший по таймауту, возвращается пустым с `timed_out = true` — сводка не ждёт медленный раздел.
- Старые `GET /workspaces/{id}/messages/search` и `/tasks/search` остаются (боты, «поиск в комнате»), внутри —
  тот же код раздела.

### 2. Права — только существующие функции (никаких новых правил)
- `messages`: комнаты из `rooms.VisibleIDs` (+ DM вызывающего при `scope=all`); исключаются комнаты задач и заметок
  (у них свои разделы).
- `task_comments`: сообщения комнат задач, для которых `perm.TaskBits ≠ 0` (полный доступ к доске **или** доступ по
  карточке, ADR-0059); выдача несёт ключ и название задачи.
- `tasks`: `boards.VisibleBoards` (полные + по карточкам с условием «приглашён»), как `search` сейчас.
- `notes`: только свои полки (`rooms.type = 'notes'` владельца) — и только при `scope=all` или явном `types=notes`.
- `events`: события, которые вызывающий видит **с деталями** по правилам календаря (`calendar.viewerOf` — организатор,
  участник, комната события с `VIEW_ROOM`); события, где ему положено только «занято» (ADR-0041/0045), в поиск не
  попадают вовсе — ни заголовок, ни факт совпадения. Повторяющиеся — одно попадание на серию + ближайшее вхождение.
- `files`: вложения сообщений из видимых комнат/DM/задач/своих заметок (через ту же видимость сообщения); удалённые
  сообщения — нет.
- `transcripts`: записи, доступные по правилу `recording.visibleRecording` (тот же код, без копии), только с готовой
  расшифровкой.
- Гости: только то, что они уже видят (их `VisibleIDs`, без досок; события — по участию). Боты: эндпоинт доступен с
  теми же правилами (`botAllow`), `notes` для ботов нет.

### 3. Поиск и индексы (PostgreSQL 17)
- **Префикс и морфология**: запрос разбирается на клиенте сервера в tsquery вида `(слово1 & слово2:*)` для russian и
  simple (последнее слово — префикс, ≥ 2 символа), кавычки и `-исключение` — как `websearch_to_tsquery`.
- **Опечатки и подстроки** для коротких полей — `pg_trgm` (trusted extension, ставится владельцем БД):
  `similarity`/`%` по заголовкам задач, названиям событий, именам файлов; ключ задачи `ABC-12` — точное совпадение
  `boards.key` + `tasks.number` (без индексов полного текста).
- **Индексы** (миграция 00064, `CREATE INDEX CONCURRENTLY`, `-- +goose NO TRANSACTION`, `lock_timeout`):
  `events` — GIN по `to_tsvector('russian'|'simple', title || ' ' || description)` + trigram по `title`; `files` —
  trigram по `name`; `tasks` — trigram по `title` (FTS-индекс уже есть); расшифровки — новая колонка
  `room_recordings.transcript_text text` (заполняется при сохранении результата из `transcript_json`, бэкфилл
  батчами в той же миграции/стартовой задаче) + GIN FTS; сообщения — существующий `messages_search_idx` (выражение
  не меняем, чтобы не перестраивать огромный индекс).
- **Ранжирование**: внутри раздела — `ts_rank_cd` × свежесть (`1 / (1 + дни/30)`), для сообщений в сводке — свежие
  совпадения первыми (как сейчас), в ленте раздела — по релевантности с переключателем «Сначала новые».
- Сниппеты — `ts_headline` только для возвращаемых строк (≤ 20), `MaxFragments=1, MaxWords=18`.

### 4. Клиент
- **⌘K** (`QuickSwitcher`): как сейчас мгновенные локальные результаты (комнаты, DM, участники, полки) + один запрос
  `/api/search` (debounce 200 мс, отмена предыдущего через `AbortController`, кэш последних 20 запросов на 60 с);
  разделы «Сообщения», «Задачи», «Комментарии», «События», «Файлы», «Заметки», «Расшифровки» по ≤ 4 строки, у каждого
  иконка, подсветка, подпись места («#разработка · Борис · 3 окт.», «FNG-12 · Доска», «Пт 10:00 · Созвон»,
  «report.pdf · #общий»); внизу каждого раздела «Все: N →». Переключатель «Это пространство | Везде» в строке поиска
  (запоминается). Клавиши: ↑↓, ↩ — открыть, ⌘↩ — «Все результаты», Tab — следующий раздел.
- **Панель «Результаты поиска»** (правая панель, как закрепы): вкладки разделов со счётчиками, фильтры — автор, комната
  /доска, период («Сегодня», «7 дней», «30 дней», даты), «Только с файлами», сортировка; бесконечная лента по курсору.
  Переходы: сообщение — прыжок в ленту (`requestJump`), задача — панель задачи, событие — карточка события, файл —
  превью с «Показать в чате», расшифровка — экран записи на нужной секунде, заметка — полка с прыжком.
- Производительность: строки `memo`, поиск не трогает сторы лент, результаты — в локальном состоянии панели.
- i18n ru/en/es/zh-CN; docs/08 — разделы ⌘K и панель.

### 5. Этапы
1. Сервер: эндпоинт, разделы `messages/tasks/task_comments/events/files/notes`, префикс, pg_trgm, индексы, тесты прав
   на каждый раздел (включая «занято» в событиях, доступ по карточке, гостей, ботов, `scope=all`).
2. Расшифровки: колонка + бэкфилл + раздел (отдельно: бэкфилл может быть долгим на проде).
3. Клиент: ⌘K + панель.
Второе (security) ревью — обязательно: новый эндпоинт агрегирует все права продукта.

### 6. Тесты и документы
Интеграционные `TestSearch*` (шарды по букве: `S` → app-4), unit на разбор запроса и сборку tsquery; vitest на
сводку ⌘K, клавиши и маркеры подсветки; `EXPLAIN` основных запросов на засеянной базе (≥ 1 млн сообщений) — в отчёт
и docs/14 (бюджет: сводка ≤ 300 мс p95 на 1 млн сообщений). Docs: 05 (новый маршрут), 16 (строка «Поиск»), 19 + .en,
08, TESTING.md, CHANGELOG.

## Не входит
Поиск по содержимому файлов (PDF/DOCX), семантический/векторный поиск, сохранённые поиски, поиск по реакциям и
стикерам, поиск по названиям комнат на сервере (остаётся локальным).

## Последствия
- Один источник правды для прав в поиске — существующие функции видимости; новый раздел = одна функция-адаптер.
- Появляется расширение `pg_trgm` — его должна поддерживать прод-БД (PG17 в k8s: trusted extension, достаточно
  прав владельца базы; проверить при деплое, миграция падает с понятной ошибкой).
