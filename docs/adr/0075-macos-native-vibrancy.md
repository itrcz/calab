# ADR-0075: Нативное стекло macOS за рейлом, колонкой и тайтлбаром (2026-10-07)

Исключение из правила «`backdrop-filter`/стекло запрещено» (владелец, 28.09; CLAUDE.md, docs/14).

## Контекст
3.0, редизайн по референсу Codex (ADR-0074). Владелец, 07.10: нужно нативное размытие окна на macOS за боковой частью и верхней панелью.

Правило 28.09 запрещает стекло из-за слабых компьютеров сотрудников. Оно направлено против CSS `backdrop-filter`: Chromium каждый кадр перерисовывает и размывает содержимое под элементом, и это нагружает GPU и CPU.

Нативный `NSVisualEffectView` устроен иначе. Его отрисовывает WindowServer (композитор macOS), а не renderer. Это тот же материал, что у боковых панелей Finder и Mail. Electron включает его опцией окна `vibrancy`. Renderer при этом ничего не перерисовывает.

## Решение
1. **Где.** Только Electron на macOS. Окно получает `vibrancy: 'sidebar'` (или ближайший материал), `visualEffectState: 'followWindow'` и прозрачный фон окна.
   - Рейл, колонка и тайтлбар — прозрачные слои поверх материала: тонкий полупрозрачный тон для читаемости в светлой и тёмной теме.
   - Область чата и контента остаётся **сплошной**.
   - Веб, Windows и Linux не меняются: там прежние сплошные материалы.
2. **Всегда включено.** Владелец, 07.10: «разрешаем на маке, отключать не нужно». Режим «слабый компьютер» стекло не выключает. Если пользователь включил в macOS «Уменьшить прозрачность», ОС сама рисует сплошной материал.
3. **CSS `backdrop-filter` по-прежнему запрещён** везде, на macOS тоже.
4. **Замер.** Перед мержем — `tools/energy-bench.py` без звонка, до и после, на Mac. Бюджет docs/14 (≤ 1 % CPU без звонка) должен сохраниться. Цифры — в docs/14.

## Последствия
- Тон рейла, колонки и тайтлбара на macOS задаётся переменными с прозрачностью. На остальных платформах те же переменные сплошные. Класс на `<html>` (`mac-vibrancy`) включает прозрачные значения.
- Скриншот-тесты Electron на macOS зависят от обоев за окном. Эталоны darwin и так не перезаписываются массово, а nightly на Linux стекла не видит.

## Альтернативы
- **CSS `backdrop-filter`:** запрещён правилом 28.09, нагружает renderer.
- **Оставить сплошные материалы:** владелец выбрал нативное стекло.

## Реализация (07.10)
- Main: `vibrancy: 'sidebar'`, `visualEffectState: 'followWindow'` — неактивное окно гаснет само, как у системных приложений. Фон окна `#00000000`, `transparent: false`.
- Renderer: корневой класс `vibrancy` ставит листовой компонент `WindowVibrancy`, только в десктопной оболочке. Вход, онбординг и телефонная раскладка остаются сплошными.
- Просвечивают тайтлбар и рейл разделов (`mat-rail`) и колонка комнат и DM (`mat-sidebar-window`). Поверх материала лежит полупрозрачный оттенок `--vibrancy-rail` / `--vibrancy-sidebar`: рейл темнее колонки, контраст текста ≥ 4,5:1 в обеих темах. Внешний вид материала следует `nativeTheme.themeSource`.
- Сплошные: лента, композер, заголовок комнаты, островок, поповеры, листы, колонка участников. Градиент `island-fade` на прозрачной колонке выключен.
- Правило в одном месте (`shared/windowMaterial.ts`, для main и renderer). Стекла нет вне macOS, при системном «Уменьшить прозрачность» и в визуальных тестах. Пользовательской настройки нет, режим «Слабый компьютер» его не выключает (владелец, 07.10).
- Прежний замер (docs/14 «Без стекла»): снятие `vibrancy` окна в пределах шума — смешивание с рабочим столом делает WindowServer. Дорогим было только CSS-размытие над видео (≈ 5,5 п. п. GPU-процесса).

## Правка (07.10, владелец): спокойнее и только верх
- Оттенок тайтлбара и рейла плотнее (≈ 86 %: тёмная тема темнее, светлая светлее) — иначе красные плашки счётчиков слишком контрастны.
- Колонка комнат и DM (`mat-sidebar-window`) снова сплошная, без прозрачности; её градиент `island-fade` возвращён. Просвечивают только тайтлбар и рейл разделов.
- Счётчики на рейле без вырезной обводки (кольцо осталось только в телефонной панели вкладок).
