# ADR-0160: Настройка доски «Согласование держит переходы» (2026-11-07)

**Статус: принято.** Дополняет [ADR-0049](0049-task-approvals.md) §2 (ворота становятся настройкой
доски, по умолчанию — как раньше); [ADR-0108](0108-approval-override-and-on-behalf.md) и
[ADR-0122](0122-owner-bot-approval-override.md) действуют на досках, где ворота включены. Задача CBF-156.

## Контекст
Владелец (05.11): «можно было менять статус задачи юзеру и ботам не сбрасывая голоса, голоса не должны
сбрасываться из-за изменения статуса задачи». Доски INV/DOC/HR ведут роботы и люди без «Управлять
доской»; статус показывает, у кого мяч, а кто и когда подтверждает — решают согласующие и код
интеграции. Ворота ADR-0049 §2 отвечают `409 TASK_APPROVAL_REQUIRED` на перевод «вперёд», пока есть
голос `pending`/`rejected`; обход `override_approval` — только у `MANAGE_BOARD`. Остальным оставалось
снять согласующих и поставить заново — то есть потерять голоса: реплей робота оплаты 04.11 так
сбросил 13 карточек INV. Другим пространствам ворота нужны как есть.

## Решение
1. **Настройка доски** `Board.approval_gate` (`APPROVAL_GATE_HOLD` | `APPROVAL_GATE_OFF`), колонка
   `boards.approval_gate_off boolean NOT NULL DEFAULT false` (миграция 00147). По умолчанию `HOLD` —
   поведение ADR-0049 §2 без изменений, включая `override_approval` и запись `approval_override`.
   Пишет `MANAGE_BOARD`: `PATCH /api/boards/{id}` `approval_gate` (`UNSPECIFIED` — 422); отдаётся в
   `GET /api/boards/{id}`, списках и `BOARD_UPDATE`, так что клиенты и боты видят режим.
2. **`OFF`**: согласование не держит ни один путь смены статуса — `PATCH` (kanban, массовые, боты сами,
   от имени владельца и участника), удаление статуса с `move_to`, смена типа статуса на `COMPLETED`
   (CBF-73), правило `set_status` и пробный прогон, создание задачи (и из формы) с согласующими сразу
   в `COMPLETED`. Нужны только обычные права правки задачи; `override_approval` не нужен и ничего не
   пишет. Перенос на другую доску смотрит настройку **целевой** доски. Одна точка — `boardGate`
   (читает настройку, только когда `checkApprovalGate` отказал бы).
3. **В обоих режимах** перевод статуса голоса не трогает (`pending`/`approved`/`rejected` остаются),
   согласующим не уходит «просят согласовать» / «согласовано / отклонено», журнал — обычное `status`.
   `PUT …/approvers` с теми же людьми в любом порядке — без изменений и без записи в журнал. Сброс
   голосов — как прежде, только правкой названия, описания или вложений описания (ADR-0049 §3).
4. **Клиент**: в «Настройки доски → Фичи», карточка «Согласование» (видна при включённых
   согласованиях) — переключатель «Согласование держит переходы» (вкл. = `HOLD`). На доске с `OFF`
   меню статусов без недоступных строк и подсказки «нужно согласование», колонки при перетаскивании
   не затемняются, массовые действия переводят все задачи; на `HOLD` — как раньше (в т.ч. «Перевести
   вручную» для руководителя). `UNSPECIFIED` от старого сервера читается как `HOLD`.

## Альтернативы
- Снять ворота везде — ломает пространства, где согласование действительно запрещает закрыть задачу.
- Флаг «требует согласования» на статусе (держать только переходы в помеченные статусы) — гибче, но
  больше UI и правил; тумблера доски достаточно для кейса, статусный флаг можно добавить позже.

## Последствия
- `computePermissions` и биты не меняются; контракт — новое поле и enum (аддитивно).
- На доске с `OFF` согласование — зафиксированное решение согласующих (тег, блок, фильтр «Ждут моего
  согласования»), а не замок на статусе.
