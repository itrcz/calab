# ADR-0168: Выключенные микрофон и звук переходят в следующую сессию и на другое устройство (2026-11-12)

**Статус: принято (12.11, CBF-180, владелец).** Дополняет docs/02 «Режимы микрофона» / «Deafen»,
docs/05 «Состояние голоса», [ADR-0134](0134-mic-state-convergence.md) (намерение в сторе — источник
правды), [ADR-0130](0130-voice-ptt-mode-flag.md) (PTT).

## Контекст

Mute микрофона и deafen жили только в сторе вкладки/окна (`useVoice`), переживали лишь перезагрузку
вкладки (sessionStorage) и рестарт для обновления. Закрыл приложение с выключенным микрофоном —
следующий вход в голос с открытым; перешёл с телефона на компьютер — состояние не переносится.
Владелец: то же устройство — как оставил; другое устройство — как на последнем активном; веб,
десктоп, телефон (общий веб-клиент, ADR-0067). PTT остаётся **на устройстве**.

## Решение

1. **Выбор пользователя хранится на сервере**: `users.voice_muted / voice_deafened / voice_mute_at`
   (миграция 00154), `PUT /api/me/voice-mute {muted, deafened}` → `VoiceMute` c `updated_at`;
   устройствам пользователя — `USER_UPDATE {me}`; ботам `403`. Читается в `UserSettings.voice_mute`
   (только чтение, `settings`-replace его не трогает) и в ответе `/join` комнаты
   (`JoinVoiceResponse.self_mute`). Last writer wins по часам сервера. Отдельный эндпоинт, а не
   `PATCH /api/me`: один `UPDATE … RETURNING`, без чтения пользователя и без гонки с заменой
   `settings` целиком.
2. **Кодировка**: `muted` — выбор микрофона; при deafen — микрофон «до deafen» (`mutedBeforeDeafen`),
   `deafened` всегда означает и выключенный микрофон (семантика Discord, `lib/voiceLogic`).
3. **Пишут только клики пользователя** (`voice.toggleMute/toggleDeafen`: кнопки, хоткеи, трей,
   системные кнопки звонка). Не пишут: модераторский mute (пока он действует, микрофонная часть
   выбора остаётся прежней, deafen поверх — пишется), автовыключение по тишине, ответ на звонок
   («ответил = говорю», разово для звонка), пропажа микрофона. Запись — сразу в localStorage
   (`calab-voice-mute`, по userId) и через 600 мс на сервер, один запрос в полёте; неотправленный
   клик (`dirty`) уходит при следующем READY.
4. **Применение**: READY / `USER_UPDATE` — только пока это устройство вне голоса (в голосе активно
   оно само: одно устройство в голосе, docs/05). Вход в комнату (не реконнект, не перенос, не звонок,
   не телефонная линия) — значение из ответа `/join` кладётся в стор **до** публикации микрофона и до
   pending-флагов: первый же опубликованный трек уже `mute()`, открытого микрофона нет ни на миг. Нет
   значения сервера (старый сервер, никогда не выбирали) — локальная копия. Неотправленный локальный
   клик сильнее значения сервера; значение старше уже виденного (запоздалое эхо) игнорируется — без
   сравнения часов устройств.
5. **PTT — на устройстве.** `micMode` больше не берётся из `UserSettings.mic_mode` на каждом READY:
   серверное значение (последний выбранный режим) только засевает устройство без своего режима
   (`prefs.micModeLocal`, один раз). PTT не входит в `VoiceMute`; mute поверх PTT — как раньше
   (нажатие клавиши при mute игнорируется), гейт PTT в выбор не пишется.

## Последствия

- Без звонка — ни таймеров, ни подписок; один индексный SELECT по PK на `/join`; ререндер только при
  реальном изменении `muted/deafened`.
- Клик, сделанный офлайн на одном устройстве, уходит при возврате связи и может перезаписать более
  поздний выбор с другого устройства (часы устройств не сравниваем) — принято.
- Два устройства одновременно: живая синхронизация только для устройства вне голоса; активное
  устройство держит своё состояние, при следующем клике его выбор перезаписывает общий.
- Старые клиенты продолжают синхронизировать `mic_mode` между собой; новые его только засевают.
