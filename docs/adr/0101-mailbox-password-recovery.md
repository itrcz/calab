# ADR-0101: Восстановление пароля почтового ящика через бота (2026-10-14)

Почтовый хостинг Calab (первый боевой домен — `gptunnel.ai`, миграция с Яндекса через визард
`mail.gptunnel.ai`, отдельный деплой) не имеет восстановления пароля ящика: пароль задаётся один
раз на шаге 3 визарда, повторный запуск миграции заблокирован («Этот ящик уже перенесён»).
Владелец, 14.10: у бота tunka (first-party бот команды) должен быть функционал проверки и
восстановления пароля почты, если ящик живёт на нашем хостинге; восстановление допустимо, когда
логин Calab совпадает с восстанавливаемой почтой, и пароль показывается один раз на экране, —
иначе каждое забытое письмо превращается в обращение к администратору.

Ограничение, определяющее архитектуру: боты не видят email участников (ADR-0077, `user.proto` —
«never for … bot viewers (bot API, webhooks)»). Проверку «логин = восстанавливаемая почта» может
сделать только сервер; бот получает результат, не адрес.

## Решение

1. **Конфигурация** (env, по образцу `SMTP_*`; пусто = фича выключена, маршруты отвечают 404):
   - `MAILHOST_ADMIN_URL` — база сервисного API хостинга;
   - `MAILHOST_ADMIN_TOKEN` — Bearer для него;
   - `MAILHOST_DOMAINS` — домены на хостинге (csv, lower case);
   - `MAILHOST_RESET_BOTS` — username ботов (csv), которым разрешены маршруты ниже.
2. **Контракт с хостингом** (реализуется на стороне хостинга):
   `POST /admin/api/mailboxes/{address}/password/reset` → `200 {"password": "…"}` — новый
   случайный пароль (≥ 16 символов), старый отзывается немедленно; пароль не логируется.
   Ошибки: `401`, `404 mailbox_not_found`, `429`.
3. **Два маршрута Bot API** (token бота, решения в `botroutes.go`):
   - `POST /api/mailbox/hosting-check {userId}` → `{hosted, domain, verified}` — домен
     подтверждённого email участника ∈ `MAILHOST_DOMAINS`; сам адрес не раскрывается;
   - `POST /api/mailbox/password-reset {userId}` → `{token, redeemUrl, expiresAt}`:
     бот ∈ allowlist; цель — участник общего с ботом пространства, не гость и не бот;
     email цели подтверждён (`email_verified_at`; иначе 403 `EMAIL_NOT_VERIFIED` — доверие к
     адресу, ADR-0065, добавить в `auth.TestEmailTrustInventory`); домен ∈ hosted; лимиты
     3/час на цель и 10/час на бота; аудит (бот, цель, время — без пароля). Сервер вызывает
     хостинг (п. 2) и кладёт `{userId, email, password}` в Redis под одноразовым токеном
     (128 бит, TTL 10 минут, изъятие `GETDEL`).
4. **Погашение** — страница `/mail-reset/<token>` (`Cache-Control: no-store`): один раз
   запрашивает `POST /api/mailbox/password/redeem {token}` → `{email, password}`; повторно
   или просрочен — 410. Показ: моноширинный пароль, «Скопировать» и «Открыть в Calab» по
   существующему паттерну `calab://mail/<base64(email:password)>` (тот же, что у визарда
   миграции и карточки «Добавить почту в Calab»). Работает и в вебе, и в мобильном WebView.
5. **Бот (tunka, вне этого репозитория)**: в DM команда восстановления → `hosting-check` →
   при `hosted=false` — «ящик не на нашем хостинге», при `verified=false` — «сначала
   подтвердите почту в настройках»; иначе `password-reset` и сообщение со ссылкой
   `redeemUrl`: «пароль покажется один раз, ссылка живёт 10 минут». Пароль сообщением бот
   не отправляет никогда.

## Безопасность

- Захват ящика исключён без доступа к DM владельца: сброс требует allowlisted-бота и
  подтверждённого адреса цели; пароль раскрывается только одноразовым токеном, пришедшим
  в личку владельцу. Неподтверждённый адрес сбросить не может и сквоттер (ADR-0065).
- Компрометация allowlisted-бота позволяет сбрасывать пароли участников (старый отзывается,
  DoS-уровень) — принимается: tunka — доверенное first-party ПО; смягчения — лимиты и аудит.
- Пароль генерирует хостинг; сервер Calab — транзит (Redis, TTL 10 мин, single-use); не
  логируется, в Postgres и в сообщениях не оказывается.

## Последствия

- Новые маршруты Bot API: дока `apps/landing/src/content/docs/{ru,en}/bots` + reference
  (маршруты, ошибки, лимиты), журнал изменений.
- Новая страница погашения — визуальная спека per-screen (`dark-960`, `iPhone 14`) и один
  прогон `-g` (правило «новые интерфейсы», 10.10).
- Интеграционные тесты: happy path; неподтверждённый email; домен не наш; бот вне allowlist;
  гость/бот как цель; одноразовость токена и TTL; лимиты.
- Включение на инстансе: четыре env из п. 1 на сервере того пространства, где живёт бот.

## Альтернативы

- **Пароль сообщением бота с автоудалением** — пароль попадает в БД сообщений и остаётся в
  истории, если удаление не случилось; нарушает «показывается один раз»; отклонено.
- **Кнопка в настройках приложения без бота** — владелец хочет вход через tunka; эндпоинт
  п. 3 позволяет добавить кнопку позже без новых сущностей.
- **Отдать боту email цели для самостоятельной проверки** — ломает приватность ADR-0077
  (боты не видят адреса); отклонено.
