# ADR-0097: Бывшие участники — след остаётся, показываем особо, список в настройках (2026-10-14)

## Контекст
Владелец, 14.10: «бывает, увольняем, но юзер уже что-то писал, где-то светился; когда убираем из пространства, он должен остаться в каком-то списке, который можно посмотреть; задачи, комментарии — всё должно сохраниться, только особым образом показываем таких пользователей».

Сейчас (`workspaces.removeMember`, `bans.createBan`, `guests.Cleanup`): удаляется только строка `workspace_members`; сообщения, файлы, задачи (исполнитель/согласующий/наблюдатель), события календаря, реакции остаются — они ссылаются на `users`. Но клиент знает профили только из `WorkspaceSnapshot.members` и событий участников: после перезагрузки автор-неучастник превращается в «Неизвестный» (`memberName` → `common.unknownUser`), аватар — заглушка, карточка профиля не открывается. Списка бывших нет. Истёкшие гостевые аккаунты анонимизируются в «Гость (удалён)».

## Решение
1. **Таблица `workspace_former_members`** `(workspace_id, user_id, display_name, avatar_file_id, nickname, role (высшая встроенная на момент ухода), joined_at, left_at, reason text CHECK IN ('left','removed','banned','guest_expired','directory_disabled'), removed_by NULL, PRIMARY KEY (workspace_id, user_id))`. Пишется в той же транзакции, что удаляет членство: выход, кик, бан, истечение гостя (§ADR-0098), отключение в каталоге. Повторное вступление удаляет строку (человек снова обычный участник). Снимок имени/аватара нужен на случай удаления/анонимизации аккаунта; пока аккаунт жив, показываем живой профиль.
2. **Профили по запросу**: `GET /api/workspaces/{id}/users?ids=a,b,…` (≤ 100 id) → `UserRef[] {user_id, display_name, avatar, username, former: bool, left_at, reason}` для любого id, который когда-либо был участником (членство или `workspace_former_members`); чужие id → пропускаются. Клиент резолвит неизвестных авторов/исполнителей пачкой (дебаунс 100 мс, кэш в `users` стора с флагом `former`), поэтому снапшот не растёт.
3. **Список бывших**: `GET /api/workspaces/{id}/former-members?guests=0|1&cursor=` — право `MANAGE_MEMBERS` (там же, где бан); вкладка «Бывшие» в Настройки → Участники рядом с «Баны»: имя, роль, «ушёл/удалён/забанен · когда · кем», поиск, переключатель «показывать гостей» (по умолчанию гости скрыты — их много и они не «сотрудники»), действие «Пригласить снова» (ссылка-приглашение) и «Открытые задачи: N» → ссылка на доски с фильтром по исполнителю.
4. **Как показываем бывших везде** (docs/08 «Бывший участник»): аватар в оттенках серого с маленьким значком «вышел» в углу (как значок замка у приватной комнаты); имя обычным цветом, рядом чип `бывший` (контур, muted, 11 px) — в ленте у первого сообщения группы, в панели задачи (исполнитель/согласующий/наблюдатель/комментарий), в истории задачи, в событии календаря; карточка профиля открывается и показывает «Бывший участник · ушёл 12.10.2026», без кнопок «Написать»/«Позвонить» (DM-история с ним остаётся доступной из «Личных»). В пикерах (упоминание, исполнитель, участники события) бывших нет; упоминание `@бывший` в старом тексте рендерится с тем же чипом и без уведомления. Задачи бывших не снимаются автоматически: в панели задачи у исполнителя-бывшего — кнопка «Переназначить» (тот же пикер); фильтр досок «Исполнитель: бывшие участники» показывает всё, что надо раздать. Диалог кика показывает «Открытых задач: N» как подсказку (массовое переназначение — v2).
5. **События**: `WORKSPACE_MEMBER_REMOVE` дополняется `former: FormerMemberInfo{left_at, reason}` — клиент помечает профиль, а не выкидывает его; при `WORKSPACE_MEMBER_ADD` флаг снимается. Нового события не нужно.
6. **Бэкфилл**: миграция добавляет в `workspace_former_members` авторов сообщений/задач пространства, у которых нет членства (reason `removed`, `left_at` = время последнего их сообщения/правки), чтобы старые «Неизвестные» получили имена.

## Последствия
- Протокол (`UserRef`, `FormerMemberInfo`, два маршрута) — Opus и второе ревью (права: `?ids=` не должен раскрывать посторонних; список — `MANAGE_MEMBERS`).
- docs/04 (таблица), docs/08 (правила показа), docs/16 (маршруты).
- Телефон: вкладка «Бывшие» в экране участников настроек; чипы — те же компоненты.

## Альтернативы
- **Профили бывших в `WorkspaceSnapshot`** — растёт бесконечно; отклонено в пользу резолва по запросу.
- **Soft-delete членства (`left_at` в `workspace_members`)** — все запросы прав/списков пришлось бы фильтровать; отдельная таблица безопаснее.
- **Автоснятие с задач при кике** — теряет информацию, владелец просил сохранять; переназначение — ручное, с подсказкой.
