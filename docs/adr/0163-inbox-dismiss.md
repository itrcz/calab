# ADR-0163: ✕ на карточке «Упоминаний» — убрать уведомление из списка (2026-11-07)

Дополняет [ADR-0141](0141-inbox-task-notices.md). Доска багов CBF-155.

## Контекст
С ADR-0141 инбокс «Упоминания» показывает все упоминания чатов и все уведомления о задачах, прочитанные
тоже, — лента бесконечна, руками её не почистить. Владелец (CBF-155): крестик в правом верхнем углу
каждой карточки убирает её из списка; убранное не возвращается после перезагрузки, перезахода и на
других устройствах; остальное не меняется.

Инбокс собирается из двух серверных списков: `GET /api/me/mentions` (строки `message_mentions` +
`message_everyone_mentions`, пересобираются при каждой правке сообщения) и `GET /api/me/task-notices`
(`task_notice_log`, строка на получателя).

## Решение
1. **Упоминание чата** — таблица `mention_dismissals (user_id, message_id)` (миграция 00150), ключ —
   сообщение, а не строка упоминания: правка, которая снова упоминает человека, его не возвращает.
   `ListMentions` пропускает убранные внутри каждой ветки (страница остаётся полной, `has_more` верен).
   Удаление сообщения стирает его строки (обработчик удаления; FK `ON DELETE CASCADE` — для жёстких
   удалений). Для `@everyone` работает так же: строка своя у каждого.
2. **Уведомление о задаче** — удаляется своя строка `task_notice_log` (история уже персональная,
   отдельной таблицы не нужно).
3. **`POST /api/me/inbox/dismiss`** с телом `InboxDismiss {message_ids, notice_ids}` (≤ 100 каждого) → 204.
   Меняются только свои строки; строка пишется только о сообщении, которое сейчас упоминает вызывающего
   (прямо или `@everyone`) — неизвестный или чужой id молча пропускается, ответ не говорит, есть ли
   такое сообщение. Маршрут `scopeGlobal` (ничего не читает из пространства), ботам разрешён (бот,
   опрашивающий `/api/me/mentions`, чистит свой список).
4. **Синхронизация** — событие `INBOX_DISMISS` (тот же `InboxDismiss`) в личный канал вызывающего, как
   `USER_BLOCKS_UPDATE`. Клиент держит множество убранных id: они не возвращаются ни из страницы
   истории, пришедшей одновременно, ни из живого `MESSAGE_CREATE/UPDATE`.
5. **Убрать = прочитать.** Непрочитанное упоминание двигает маркер комнаты до него (как клик по
   карточке); убранное уведомление задачи с точкой (новейшее по задаче) снимает «непрочитано» задачи.
   Более старое уведомление задачу не читает — точка останется на новейшем. Делает клиент существующими
   вызовами (`PUT /rooms/{id}/read`, `PUT /tasks/{id}/read`), у них своя синхронизация.
6. **Клиент**: ✕ — `IconButton` sm (44 px на телефоне) в углу карточки, рядом с её кнопкой (вложить
   кнопку в кнопку нельзя), поповер не закрывается. Удаление оптимистичное; отказ сервера возвращает
   карточку и показывает тост.

## Не в этой версии
Отмена через тост «Вернуть» (готового паттерна отмены в тостах нет; уведомление задачи удаляется
насовсем) и «Очистить все прочитанные» — в docs/09. Телефонного инбокса нет (на телефоне нет
титлбара) — крестик появится вместе с ним.
