# ADR-0155: Лимиты загрузки файлов — env по умолчанию, переопределение суперадмином на пространство (2026-11-02)

Доска #144. Люди бросали в Диск много файлов разом и получали ошибки: частота загрузок была зашита в
`app.go` (30 сразу, потом 2 в минуту = 120 в час → 429), клиент Диска на 429 просто ронял файл.
Владелец (02.11): по умолчанию файл до 1 ГБ, 50 загрузок сразу, потом 500 в час; менять — из
админки, на пространство.

## Решение

1. **Умолчания — env**: `MAX_FILE_SIZE_MB=1024`, `UPLOAD_RATE_BURST=50`, `UPLOAD_RATE_PER_HOUR=500`
   (token bucket в Valkey на пользователя, общий для всех его пространств и DM, как раньше).
2. **Переопределение — на пространство, суперадмином** (ADR-0024): `workspaces.upload_burst`,
   `upload_per_hour`, `max_file_mb` (NULL = env), `PUT /api/admin/workspaces/{id}/upload-limits`,
   карточка «Загрузка файлов» в админке. Диапазоны: 1..10000, 1..100000, 1..4096 МБ. Каждая правка —
   строка `workspace_admin_log` (`action = 'upload_limits'`). Не часть тарифа: это эксплуатационная
   настройка (большой клиент с архивом, злоупотребление), а не продаваемый лимит — в `PlanLimits` и
   журнал тарифа не попадает.
3. **Где действует**: все загрузки в пространство через `files.UploadWith` (вложения чата, Диск, доски,
   вики) и копия файла в Диск (`CopyInto`). Значения читаются со строкой пространства на каждой загрузке —
   без перезапуска. Пространство с переопределённой частотой получает свой bucket
   `rl:upload:<user>:<ws>`, чтобы не делить его с умолчанием. DM и заметки — всегда env. Формы досок —
   свой `max_file_mb` (ADR-0064), не выше `MAX_FILE_SIZE_MB`.
4. **Жёсткий потолок файла — 4096 МБ** (`config.MaxFileSizeCapMB`, и env, и переопределение). Загрузка —
   один потоковый запрос без докачки: 4 ГиБ держат соединение ~35 мин на 2 МБ/с и после обрыва начинаются
   заново; больше — только с возобновляемой загрузкой. Срок чтения запроса растёт с лимитом (не меньше
   15 мин, иначе по 512 КиБ/с), так же — срок записи при скачивании.
5. **Неприкреплённые загрузки**: потолок «загружено, но не прикреплено» был 1 ГиБ — с файлом 1 ГБ отказал
   бы первому же вложению. Теперь `max(1 ГиБ, 2 × лимит файла + 2 МиБ)`: текущий файл и предыдущий,
   ещё не прикреплённый.
6. **Ответы**: 413 `FILE_TOO_LARGE` несёт `ApiError.limit` (байты) — клиент пишет «Больше лимита N на
   файл» на своём языке; 429 — с `Retry-After`. Очередь Диска на 429 не роняет файл: строка «Ждёт
   лимита загрузок», повтор после `Retry-After` (без него — 30 с, не больше часа), слот держится — очередь
   за ним ждёт.

## Последствия

- Прокси перед API должен пропускать тело ≥ лимита и не обрывать долгую загрузку (ingress Nginx:
  `proxy-body-size`, `proxy-request-buffering`, таймауты) — список для девопса в docs/06.
- Вне Диска (чат, вики) 429 по-прежнему ошибка строки — отдельная задача, если понадобится.
