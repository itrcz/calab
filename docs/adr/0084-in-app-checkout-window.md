# ADR-0084. Оплата внутри приложения: окно checkout на десктопе

Статус: принято (2026-10-10). Меняет ADR-0080 §13 («Desktop/mobile hosted checkout — системный
браузер») для десктопа; веб и телефон — без изменений по сути.
Владелец (2026-10-10): «в приложении наверное нужно как-то запускать форму браузерную внутри,
чтобы все бесшовно было гладко»; СБП на десктопе — QR для телефона, на телефоне — выбор банка и
переход в приложение банка.

## Решение

### 1. Десктоп (Electron): модальное окно checkout
- `platform.app.openCheckout(url)` → IPC `app:open-checkout` (только из главного окна) →
  `main/checkoutWindow.ts`. Окно стартует **только** на хосте провайдера из списка
  `checkoutPolicy.CHECKOUT_START_HOSTS` (`checkout.stripe.com`, `merch.securepaytb.ru` — ссылка
  Точки, `merch.tochka.com`) + `CALABA_CHECKOUT_HOSTS` (env, песочницы/стенд). Https, без
  учётных данных, без порта. Отказ main → рендерер открывает системный браузер, как раньше.
- Модальное дочернее окно главного (на macOS — sheet). Шапка — свой вид без JS (замок + хост
  страницы + «Отмена»), страница провайдера — `WebContentsView`: без preload, `sandbox`,
  `contextIsolation`, без Node, `webviewTag` off, DevTools только в непакованной сборке, своя
  in-memory сессия (`partition: checkout`, не `persist:`), очищается при закрытии; все запросы
  разрешений, устройства, захват экрана, загрузки — отказ; http-запросы режутся в сессии.
- После старта страница может переходить на любой https (3DS банка-эмитента — произвольные
  хосты), не на http/data/file/javascript/свои схемы. `window.open` — всегда отказ, во внешний
  мир ничего не передаётся.
- **СБП на десктопе:** у плательщика нет приложения банка рядом — он сканирует QR страницы
  Точки телефоном. Переходы на `bankNNN://`, `qr.nspk.ru`, `sub.nspk.ru` отклоняются, окно
  остаётся на QR. QR рисует сама страница Точки (платёжная ссылка с `paymentModes=[sbp]`; окно
  убирает токен `Electron` из UA — страница видит обычный десктопный Chrome).
- Возврат: переход на `<сервер>/api/billing/return` (`BILLING_PUBLIC_RETURN_URL`, успех и отмена —
  один адрес) или `https://<родительский домен сервера>/onpay/success|fail` (страницы лендинга из
  настроек мерчанта Точки) → окно закрывается, рендерер получает исход (`returned` / `success` /
  `fail` / `closed`). Хосты возврата выводятся из адреса сервера, в коде их нет.
- Исход — только подсказка: открытый диалог сразу опрашивает checkout (`useCheckoutPoll`), правда —
  в ответе сервера; активация тарифа — по-прежнему ровно один раз (`credited` в PlansDialog).

### 2. Веб
Без изменений: checkout в новой вкладке, диалог опрашивает. На десктопном браузере страница
Точки сама показывает QR, на телефоне — выбор банка.

### 3. Телефон (оболочка Expo, ADR-0067)
- iOS: покупки в нативной оболочке скрыты (`sessionActivity`, docs/mobile/shared-web-status.md),
  checkout там не открывается.
- Android: checkout уходит в системный браузер (`window.open` → `Linking`), страница Точки
  показывает выбор банка, ссылки `qr.nspk.ru` / `bankNNN://` открывают приложение банка;
  вернувшись в Calab, диалог опрашивает по `visibilitychange`. Оболочка теперь тоже отдаёт ОС
  ссылки `bankNNN://` (раньше блокировались) — на случай, если такая ссылка придёт в WebView.
- Не делаем сейчас: Custom Tabs / SFSafariViewController (`expo-web-browser`) — новая нативная
  зависимость и новый бинарник; возврат в приложение по https-адресу требует App Links /
  Universal Links. Отдельная задача.

### 4. Не используем
Отдельный API QR СБП Точки (`/sbp/…`, payload + картинка): другой продукт (регистрация ТСП в
СБП), меняет сервер и контракт. Возвращаемся к нему, только если живая страница платёжной ссылки
не покажет QR на десктопе.

## Последствия
- Карта и 3DS не проходят через наш код: страница провайдера в изолированной сессии без моста.
- Новый хост ссылки Точки — правка `CHECKOUT_START_HOSTS` (до неё — системный браузер, не поломка).
