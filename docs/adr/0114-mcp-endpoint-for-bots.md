# ADR-0114: MCP-эндпоинт для ботов (2026-10-21)

**Статус: принято; п. 2 и «Что не делаем» про «от имени» изменены [ADR-0156](0156-mcp-on-behalf-and-via-mark.md).** Опирается на [ADR-0031](0031-bots.md) (боты, токен, лимит запросов),
[ADR-0109](0109-bot-rights-like-people.md) (таблица маршрутов бота), [ADR-0106](0106-bot-acts-as-owner.md) и
[ADR-0111](0111-bot-acts-for-consenting-member.md) (от имени владельца / участника). Задача CBF-48.

## Контекст
Владельцы ботов подключают к Calab LLM-клиентов (Claude, IDE-агенты и т. п.). Сейчас для этого нужен свой
адаптер поверх REST. Model Context Protocol — общий для таких клиентов способ дать модели инструменты: клиенту
достаточно URL и заголовка `Authorization`. Нужно дать модели минимальный набор действий (найти, прочитать,
создать задачу, прокомментировать, сменить статус, написать в комнату), не создавая второго пути к данным со
своими проверками прав.

## Решение
1. **Эндпоинт `/api/mcp`** (`internal/mcp`): JSON-RPC 2.0 поверх Streamable HTTP, только `POST`, ответ —
   один JSON-объект; без сессий (`Mcp-Session-Id`), без серверного потока (`GET`/`DELETE` → 405). Методы:
   `initialize` (версия — версия клиента из поддерживаемых `2025-11-25`, `2025-06-18`, `2025-03-26`,
   `2024-11-05`, иначе новейшая), `ping`, `tools/list`, `tools/call`; уведомления → 202 без действия.
   Пакеты (batch) — 400, тело > 1 МиБ — 413, неизвестный метод −32601, неизвестный инструмент −32602.
2. **Только токен бота.** Маршрут — `private` (нет токена → 401), обработчик отказывает всему, что не
   `Identity.IsBot` (человек, сессия, «от имени» → 403). В таблице маршрутов бота — `botAllow` +
   `onBehalfClosed`: `Calab-On-Behalf` на эндпоинте закрыт, во внутренние вызовы заголовок не передаётся.
   Эндпоинт — сам бот.
3. **Инструмент = вызов REST в процессе.** Каждый инструмент вызывает обычные маршруты (`/api/search`,
   `/api/tasks/…`, `/api/rooms/…/messages`, …) через полный обработчик сервера с тем же `Authorization`:
   `auth.Require`, таблица маршрутов бота, лимит запросов бота, identity-гейт, модерация и проверки прав
   обработчика применяются как к REST-вызову бота. Своих запросов к БД и своих проверок прав у MCP нет —
   инструмент не может дать боту больше, чем его токен. Внутренний запрос — с новым контекстом (без
   идентичности и mutation-границы внешнего), сетевого вызова нет; аргументы попадают в путь через
   `url.PathEscape` (один сегмент) и в query через `url.Values`. Сам `/api/mcp` в identity-гейте —
   `scopePublic` (ничего не читает и не пишет, mutation-границы не держит).
4. **Экономия токенов модели:** шесть инструментов (`find`, `read`, `create_task`, `comment_task`,
   `set_task_status`, `send_message`), описания в строку, ответы компактные (без пустых полей); полный объект
   API — только `read` с `full: true`. Отказ REST — результат инструмента с `isError` и кодом (`404 NOT_FOUND:
   …`), чтобы модель исправила аргументы или остановилась.
5. **Лимиты — бота:** вызов инструмента стоит 1 запрос + его REST-вызовы в лимите ADR-0031.

## Последствия
- Новый маршрут REST, доступный боту, автоматически доступен и инструменту, который его вызывает; новый
  инструмент — только поверх существующего маршрута, с тестом отказа на приватной доске / комнате.
- Внутренние вызовы видны в метриках и логе `http` как обычные запросы бота (свой request id).
- `find` без `workspace` обходит все пространства бота (комнаты, доски) — у бота во многих пространствах
  один вызов тратит заметную долю лимита; при упоре в лимит инструмент возвращает 429 как ошибку.

## Что не делаем
- **Аудит вызовов инструментов** отдельным журналом — по решению владельца от 21.10 не нужен: действия
  попадают в обычные журналы (задачи, сообщения) как действия бота.
- **Стриминговый транспорт** (SSE-ответы, `GET`-поток, сессии, возобновление) пока не поддержан: инструменты
  короткие, уведомления сервера не нужны.
- OAuth-авторизация MCP (protected resource metadata) — сделано в [ADR-0158](0158-mcp-oauth-personal-access.md) для личного входа; бот по-прежнему со статическим токеном.
- Пакеты JSON-RPC, ресурсы и промпты MCP, `structuredContent`.
- «От имени» владельца или участника через MCP.
