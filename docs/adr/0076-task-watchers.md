# ADR-0076: Наблюдатели задачи и доступ по карточке на закрытых досках (2026-10-07)

**Статус: принято.** Расширяет [ADR-0059](0059-task-scoped-access.md) (доступ по карточке). Меняет решение владельца от 03.10 о закрытых досках. Релиз — 3.0.

## Контекст
Владелец, 07.10:
- если исполнителем или согласующим выбрали человека без доступа к доске, это не должно запрещаться: человеку начинает показываться задача;
- нужна сущность «наблюдатели» — сотрудники, которые видят карточку;
- упомянутый в комментарии автоматически становится наблюдателем;
- удалили из наблюдателей — человек теряет доступ, если у него нет иного.

По ADR-0059 такое уже работает для исполнителей и согласующих, кроме закрытых (`restricted`) досок. Наблюдателей не было. Подписчики (`task_subscribers`) только получают уведомления и доступа не дают: подписаться может лишь тот, кто уже видит доску.

Ответы владельца, 07.10:
- закрытые доски — разрешить;
- открывать карточку постороннему может только тот, кто может править задачу;
- гости — нет, как сейчас.

## Решение
1. **Наблюдатель** — явная роль на задаче: столбец `task_subscribers.watcher boolean NOT NULL DEFAULT false`, миграция. Наблюдатель всегда и подписчик (получает уведомления). Обычная подписка (автор, самоподписка, упоминание без права правки) наблюдателем не делает и доступа не даёт.
   - Почему отдельный флаг, а не «любой подписчик». Человек, которого убрали с приватной доски, остался бы подписчиком и сохранил бы доступ к карточке. Доступ дают только явные назначения.
2. **Доступ по карточке (ADR-0059 §1) — теперь три основания:** исполнитель, согласующий или наблюдатель живой задачи. Условие «доска не `restricted`» снимается для всех трёх (владелец, 07.10). Гости и боты — как раньше: гостей не зовём, ботам нужен `VIEW_BOARD`.
3. **Права на карточке** (`perm.TaskBits` / `taskPermissions`, зеркально Go/TS, общая таблица случаев). Наблюдатель по карточке получает `VIEW_BOARD`, как согласующий по карточке: смотреть, комментировать, подписываться. Править, создавать и голосовать он не может. Сигнатура: `TaskBits(acc, assignee, approver, watcher)`.
4. **Кто может назначать** человека без доступа к доске (исполнителем, согласующим, наблюдателем) — тот, кто может править задачу (`canEdit`). Иначе позванный со стороны мог бы звать дальше по цепочке. Сюда относится и участник по карточке с правом правки: исполнитель может звать на свою карточку.
   - Тот, кто только комментирует, упоминанием подписывает лишь тех, кто доску и так видит (как сейчас), и наблюдателей не создаёт.
5. **Упоминание в комментарии или описании** от того, кто может править задачу. Упомянутые участники пространства (не гости, не боты) становятся наблюдателями: `watcher = true`, подписка. Если у них нет доступа к доске, им открывается карточка, и приходит уведомление «вас упомянули».
6. **Снятие.** Наблюдателя убирает тот, кто может править задачу, или он сам («Перестать наблюдать»). Снятие убирает `watcher`; подписку тоже, если человек больше не видит задачу. Доступ пропадает, если не осталось других оснований: роли на доске, исполнителя, согласующего. Это производное состояние, как в ADR-0059.
7. **Интерфейс.**
   - В карточке задачи поле «Наблюдатели» рядом с «Исполнители» и «Согласование»: аватары, «+ Добавить», удаление по наведению или ✕.
   - Выбор людей в исполнители, согласующие и наблюдатели показывает **всех участников пространства** (кроме гостей и ботов без доступа). Тех, кто не видит доску, помечаем: «увидит только эту задачу».
   - Фильтр задач и `TASK_FIELD_SUBSCRIBER` — без изменений. Новое поле `TASK_FIELD_WATCHER` нужно, если поле правится через общий путь полей.
8. **Протокол.** `Task.watcher_ids` (или `watchers`) в задаче. Действия «добавить / убрать наблюдателя» — по образцу исполнителей. После `make gen` сгенерированный код коммитится вместе с `.proto`.

## Последствия
- Закрытая доска перестаёт быть абсолютно закрытой. Карточку на ней видит всякий, кого позвал редактор задачи. В настройках доступа закрытой доски показываем «Позванные по карточкам: N».
- Изменение прав и протокола: Opus, второе независимое ревью (CLAUDE.md §5).
- Уведомления (`notify.sees`) считают «видит задачу» через новую `TaskBits`.

## Альтернативы
- **Любой подписчик даёт доступ:** утечка после снятия с доски, отклонено.
- **Новый бит роли на доске:** причины против — те же, что в ADR-0059 §1.
