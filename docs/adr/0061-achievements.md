# ADR-0061: Ачивки — каталог хоста, вручение участникам, открытка в общем чате (2026-10-03)

**Статус: принято.** Релиз — следующий минорный после 2.1.0 (вместе с ADR-0059/0060). Миграция **00061**
(00060 — ADR-0059). События шлюза: новых нет (см. §4). Опирается на: бейджи участников (docs/04 «Бейджи»,
docs/09 #82), открытку дня рождения (docs/09 #76, `internal/birthdays`, `SystemMessage.birthday`), суперадминку
(ADR-0024, `admin.proto`, `features/admin/AdminWindow.tsx`), пайплайн картинок (`files.PrepareBackground`,
`gen2brain/webp`), профиль участника (ADR-0051, `ProfileCard` / `ProfileDialog`).

## Контекст
Владелец (03.10): «я буду заливать в админку картинки с прозрачным фоном; далее админы могут назначать сотрудникам
ачивки, и мы их показываем в профиле пользователя + в общем чате, если при назначении не убрать галочку
„отправить в общий чат“; сделать красиво, цивильно». Уточнения (03.10): **текст «за что» обязателен и короткий** — виден по
клику на ачивку в профиле и в открытке в чате; **при открытии ачивки — анимация блика на картинке и лёгкий наклон за
курсором, «слегка совсем»** (осознанное исключение владельца из правила «тяжёлые эффекты только на видимом»: только в
открытом просмотре, только от движения курсора, см. §5). Примеры — 21 вариант («Ачивки — 21 вариант»: 7 тем × 3 стиля:
эмалевая медаль, металлический шильдик, объёмный значок), WebP 512×512 с альфой, 17–41 КБ; оригиналы PNG 1254×1254.

## Решение

### 1. Модель
```
achievements         id uuidv7, title (1..60), description (0..200), image_key text (ключ blob.Store
                     "achievements/<uuid>.webp"), image_size int, width, height, position int, created_by → users,
                     created_at, updated_at, archived_at?            -- каталог ХОСТА: один на инсталляцию, не пространства
member_achievements  id uuidv7, workspace_id → workspaces CASCADE, user_id → users CASCADE, achievement_id → achievements
                     RESTRICT, granted_by → users SET NULL, note (1..120, «за что» — обязательно), message_id → messages SET NULL
                     (открытка в чате, если была), granted_at, revoked_at?, revoked_by?
                     INDEX (workspace_id, user_id, granted_at DESC) WHERE revoked_at IS NULL; INDEX (achievement_id)
```
- Каталог — **уровня хоста**: его ведёт суперадмин (`SUPERADMIN_EMAILS`), пространства из него только выбирают.
  Свои ачивки пространства — не в этой версии (бэклог, docs/12). Тариф не ограничивает: ачивки доступны всем
  пространствам (это витрина продукта; владелец про тариф не говорил — решение лида, легко ужесточить флагом в
  `plans/limits.go`).
- Одну и ту же ачивку можно вручить повторно (например «Получал премию» — дважды): в профиле стопка с «×2».
  Отзыв (`revoked_at`) — ачивка исчезает из профиля, открытка в чате остаётся (история не правится), счётчик
  в каталоге считает только живые.
- Архив ачивки в каталоге (`archived_at`) — вручать нельзя, вручённые остаются видны. Удалить насовсем можно только
  ачивку без вручений (иначе 409 `ACHIEVEMENT_IN_USE`) — поэтому `RESTRICT`.

### 2. Картинка
- Загрузка в суперадминке: PNG или WebP **с альфа-каналом** (без альфы — 422 `IMAGE_NEEDS_ALPHA`: фон должен быть
  прозрачным), ≤ 4 МБ, сторона 128..2048. Сервер сам делает финальный файл (`files.PrepareAchievement`, по образцу
  `BackgroundImages`): обрезка по непрозрачному bounding-box с полем 4 %, вписать в квадрат 512×512 (центр, прозрачные
  поля; CatmullRom), WebP с альфой `webp.Options{Quality: 85}` (примеры владельца — q50 17–41 КБ; q85 даёт ≤ ~100 КБ).
  Кладётся в `blob.Store` ключом `achievements/<uuid>.webp` (вне квот пространств — это файлы хоста, не строки `files`).
  Замена картинки — новый ключ, старый удаляется после коммита (как сироты).
- Отдача: `GET /api/achievements/images/{key}.webp` — любой аутентифицированный (и гость), `Cache-Control: public,
  max-age=31536000, immutable` (ключ меняется вместе с байтами), `nosniff`, `image/webp`. Нет `files`-записи — нет
  `CanRead`-цепочки; классификация в route census — «аутентифицированный агрегат» (как список стикерпаков), identity
  scope не нужен: картинка одна для всех пространств.
- Клиент показывает картинку на любом фоне без подложки (прозрачность и есть смысл) — размеры 24 / 40 / 64 / 96 / 160.

### 3. Права и API
Суперадмин (`/api/admin/achievements*`, `plans.Admin`-guard, 404 посторонним, 60/мин):
- `GET /api/admin/achievements` → `AdminListAchievementsResponse { achievements: [AdminAchievement {Achievement,
  granted_count, workspaces_count}] }` (включая архивные), `POST …` multipart `image` + `title` + `description` →
  `Achievement`, `PATCH …/{id}` `{title?, description?, position?, archived?}` + multipart `image?`, `DELETE …/{id}`
  (409 при вручениях).
Пространство:
- `GET /api/achievements` → каталог для всех аутентифицированных (живые, по `position`) — `ListAchievementsResponse`;
  клиент кэширует по `ETag` (меняется на любое изменение каталога).
- `POST /api/workspaces/{id}/members/{userId}/achievements` `GrantAchievementRequest {achievement_id, note (1..120,
  обязательно; пусто/пробелы — 422), announce (bool, по умолчанию true — proto3: клиент шлёт явно)}` → `MemberAchievement`.
  Право — `MANAGE_MEMBERS`
  (как библиотека бейджей, ADR-0048); получатель — участник пространства, не гость, не бот; **себе нельзя** (422
  `SELF_GRANT`); ачивка не архивная. Бот-токен — 403 `BOT_NOT_ALLOWED` (вручают люди; автовручение — ADR-0060 бэклог).
- `DELETE /api/workspaces/{id}/members/{userId}/achievements/{grantId}` — отзыв, `MANAGE_MEMBERS`.
- `GET /api/workspaces/{id}/members/{userId}/achievements` → `ListMemberAchievementsResponse { items: [MemberAchievement
  {id, achievement_id, note, granted_by, granted_at, message_id, room_id}] }` — живые, новые первыми; видит любой участник
  (гость — только видимых ему участников, правило профиля ADR-0051); бот — читает.
- `WorkspaceMember.achievement_count = <следующий номер>` — число живых ачивок; меняется → `WORKSPACE_MEMBER_UPDATE`
  (клиент по нему инвалидирует кэш профиля и показывает маркер). Новых событий шлюза не нужно.
- Все мутации — через admission-транзакцию (`db.TxRaw`/`GuardValue`, ADR-0058 §0); суперадминка — хостовая, без
  identity-политики (как планы).

### 4. Открытка в общем чате
- `announce = true` → в той же транзакции сервер создаёт **системное сообщение** `SystemMessage.achievement =
  AchievementCard { achievement_id, grant_id, note, granted_by }` (`payload = 4` в oneof), `kind = SYSTEM`,
  `author_id = получатель` (как открытка дня рождения: аватар и имя получателя в шапке), в комнату по правилу открыток:
  запрос `ListBirthdayRooms` → вынести общий `AnnouncementRoom(workspace)` (первая текстовая, не приватная
  предпочтительнее; `greetingRoomId` на клиенте — то же правило). Нет текстовой комнаты — вручение проходит, открытки нет,
  ответ `MemberAchievement.message_id` пуст; клиент заранее прячет галочку и пишет «В пространстве нет общего чата».
- Открытка упоминает получателя: `saveMentions` для `user_id` получателя — он получает уведомление как на `@`-упоминание
  (инбокс «Упоминания», push на мобильном вебе, нативное — по существующим настройкам). Отдельных уведомлений нет.
- Реакции, ответы, закреп, пересылка — как у любого сообщения (копия открытки никого не упоминает, ADR-0033).
  Правка/удаление — только `MANAGE_MESSAGES` (системное). Отзыв ачивки открытку не трогает.
- Вебхуки ботов/`messageCreate` видят обычное системное сообщение с `system.achievement`.

### 5. Клиент (`docs/08` — новый раздел «Ачивки»; обязательно по дизайн-системе, без `backdrop-filter`)
- **Открытка в чате** (`features/chat/AchievementCard.tsx`, по образцу открытки дня рождения, docs/09 #76): поверхность
  `.achievement-surface` — сплошной градиент токенов (`--color-accent-strong` → новый `--color-achievement-warm`, тёплое
  золото; тёмная/светлая тема — через токены), радиус карточки, тень карточки. Слева картинка 96 px без подложки, справа:
  overline «ДОСТИЖЕНИЕ» caption/uppercase 70 %, заголовок body semibold «Больше года», строка «**Имя** получает ачивку» (имя —
  открывает профиль), под ней `note` («за что») в кавычках — всегда, и caption «Вручил(а) Имя · 3 окт.». Клик по
  картинке или названию — просмотр ачивки (ниже). Мобильный веб —
  картинка 64, текст столбиком. Анимаций нет (ни бесконечных, ни на вход): «красиво» — за счёт картинки и типографики.
- **Профиль** (`ProfileCard` — поповер): после строки роли — ряд «Достижения»: до 6 картинок 28 px внахлёст −6 px,
  «+N» чипом; подсказка — название. `ProfileDialog`: секция «Достижения» (после «Роли»): сетка карточек — картинка 64,
  название, caption «3 окт. 2026 · от Имя», `note` одной строкой (обрезка, полностью — в просмотре); `×2` бейджем на картинке при повторе; клик по карточке —
  просмотр ачивки; у `MANAGE_MEMBERS` —
  меню «⋯» → «Отозвать» с подтверждением и кнопка «Вручить ещё». Пусто — строка muted «Пока нет достижений»
  (для себя — без секции вовсе). Данные — `GET …/achievements` по открытию (react-query, ключ по user, инвалидация
  на `WORKSPACE_MEMBER_UPDATE` с изменившимся `achievementCount`).
- **Просмотр ачивки** (`features/people/AchievementView.tsx`, модальный лист 360 px / на телефоне шторка; открывается
  из открытки, профиля и каталога суперадминки): картинка 160 px по центру на сплошной поверхности `.achievement-surface`,
  ниже название (title semibold), описание из каталога (muted), блок «За что» — `note` крупно в кавычках (body), caption
  «Вручил(а) Имя · 3 октября 2026», для повторов — список вручений (дата · от кого · за что). Кнопка «Открыть в чате»,
  если есть открытка. **Единственное место с эффектами** (владелец, 03.10): (1) одноразовый блик — псевдоэлемент с
  линейным градиентом, `transform: translateX` по картинке 900 мс `ease-out` один раз при открытии (CSS-анимация с
  `animation-iteration-count: 1`, не таймер); (2) наклон за курсором — `transform: perspective(600px) rotateX/rotateY`
  ≤ 6° по положению курсора над картинкой, обновление в `requestAnimationFrame` только на `pointermove` над областью
  (нет движения — нет работы), возврат в 0 при уходе с `transition 300 ms`; маска картинки не меняется, тени не
  пересчитываются (`will-change: transform` только на картинке). Оба эффекта выключены при `prefers-reduced-motion`
  и в режиме «слабый компьютер»; на тач-устройствах наклона нет. Бюджет: пока лист открыт и курсор неподвижен — 0 %
  CPU; проверить `tools/energy-bench.py`-сценарием «открыт просмотр ачивки».
- **Вручение** (`features/people/GrantAchievementDialog.tsx`): пункт меню участника «Вручить ачивку…» (иконка `Award`,
  между «Роли» и «Переместить», только при `MANAGE_MEMBERS`, не себе, не гостю/боту) и кнопка в `ProfileDialog`. Диалог
  440 px: заголовок «Вручить ачивку — Имя», поиск по названию, сетка плиток 88 px (картинка 64 + название 2 строки,
  выбранная — рамка акцента), поле «За что» (обязательно, 1..120, счётчик, placeholder «Коротко: за что вручаете», кнопка «Вручить» disabled, пока
  пусто), Toggle «Рассказать в общем чате → #general» (по
  умолчанию вкл; нет текстовой комнаты — скрыт с пояснением), кнопка «Вручить» (primary). После — тост «Ачивка вручена»
  с действием «Открыть в чате» (если открытка есть). Клавиши: ↑↓←→ по сетке, ⌘↩ — вручить.
- **Суперадминка** (`AdminWindow` — вкладка «Ачивки» рядом с пространствами): список (картинка 40, название, описание,
  «вручено N в M пространствах», позиция D&D), «Добавить» — дроп-зона PNG/WebP с проверкой альфы на клиенте до
  отправки (`lib/achievementPrepare`: читает в canvas, проверяет наличие прозрачных пикселей, предупреждает «фон не
  прозрачный» — сервер всё равно проверяет), поля название/описание; редактирование, «В архив», удаление (disabled с
  подсказкой при вручениях). Предпросмотр на светлом и тёмном фоне (как `index.html` владельца).
- **Производительность**: картинки только в видимых карточках (`loading="lazy"`), профиль — запрос по открытию; в
  колонке участников ачивки не показываем (ничего не меняется на каждый грант). i18n ru/en/es/zh-CN.
- Визуальные прогоны не запускаем; QA-проход скриншотами (Sonnet): открытка dark/light, профиль, диалог вручения,
  суперадминка.

## Не входит
Свои ачивки пространства; автоматическое вручение («год в компании» — кандидат в правила ADR-0060); тарифные лимиты;
ачивки в колонке участников и в шапке сообщений; анимации в самой открытке и в профиле (эффекты — только в просмотре).

## Последствия
- Появляется первая сущность уровня хоста с байтами в `blob.Store` вне `files` — простой путь для будущих хостовых
  ассетов (ключ-пространство `achievements/`).
- Открытка — обычное системное сообщение: история, поиск, реакции и боты работают без спецкода.
