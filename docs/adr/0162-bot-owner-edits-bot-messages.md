# ADR-0162: Владелец бота правит сообщения своего бота (2026-11-07)

**Статус: принято.** Меняет п. 6 [ADR-0151](0151-bot-owner-task-author.md) для сообщений; опирается на
[ADR-0031](0031-bots.md) (`bots.owner_user_id`) и [ADR-0106](0106-bot-acts-as-owner.md) (владелец управляет ботом
в его домашнем пространстве). Задача доски #164.

## Контекст
Скрепка пишет комментарии в карточках и сообщения в комнатах. Ошибку в тексте её владелец поправить не мог:
`PATCH /api/messages/{id}` пускал только автора (п. 6 ADR-0151: «владелец не правит сообщения своего бота»).
Оставалось удалить сообщение (и потерять его место в переписке) или идти в API с токеном бота — то есть право
у владельца и так было, только неудобным путём.

## Решение
1. **То же определение автора, что у задач.** `perm.MessageAuthor(author, botOwner, user)` — обёртка над
   `perm.TaskAuthor`: автор сообщения **или** текущий владелец бота-автора. Через него идёт только правка
   (`messages.update`, `Handlers.editor`). TS-зеркало — `isMessageAuthor` в `packages/protocol` (поверх
   `isTaskAuthor`), клиент — `mayEditMessage` (`features/chat/editable.ts`) с `READY.my_bot_ids`.
2. **Граница — домашнее пространство бота** (как в ADR-0151 §1). Владелец резолвится запросом
   `GetMessageBotOwner` только для чужого сообщения (своё — без запроса): в комнате и комнате задачи —
   `bots.workspace_id` = пространство комнаты; в DM (без пространства) — владелец всё ещё участник домашнего
   пространства бота (там он им управляет, `owner_active` ADR-0106). Нет строки — не бот, бот удалён или чужое
   пространство → `403`. Владелец текущий, без хранения: сменился — право переходит, прежний получает `403`.
3. **Доступ — свой.** Сообщение сначала грузится с правами самого владельца (`load` → `rooms.Access`):
   комнату, DM бота с другим человеком или карточку, которых он не видит, — `404`, как любое скрытое. Остальные
   проверки правки — те же: системные сообщения, стикеры и пересланные копии не правятся; блок в DM (ADR-0154)
   проверяется для владельца.
4. **Что меняет правка.** Автор остаётся ботом, `edited_at` ставится («изменено»), `MESSAGE_UPDATE` прежней
   формы. Клавиатуру владелец не трогает (передать её — `403`, как любому человеку): она сохраняется,
   `keyboardRevision` растёт, как при любой правке текста. Упоминания пересчитываются по правам правящего
   (как у всякой правки), `@nick` разрешается видимостью правящего. Поиск по комментариям задач — как при
   обычной правке. Журнал задачи (`comment_edit`) записывает **правящего** (`TaskCommentChange.Actor`) —
   владельца, не бота; вебхук доски — тоже с ним.
5. **Не меняется.** Удаление по-прежнему: своё или `MANAGE_MESSAGES` (п. «заодно» задачи #164 не взят — это
   отдельное право модерации). `MANAGE_BOTS` без владения ничего не даёт. Бот правит свои сообщения через API,
   как раньше. Стрелка ↑ в поле ввода берёт только собственное сообщение человека.

## Безопасность
Владелец и так может править через токен бота (ADR-0031/0106), поэтому новое право ничего не добавляет к его
возможностям; доступ к сообщению проверяется по его собственным правам, а не по правам бота. Чужое
пространство (бота туда добавили администраторы) и прежний владелец права не получают.

## Последствия
- Клиент не знает домашнего пространства бота (`my_bot_ids` без него): в чужом пространстве пункт «Изменить»
  может появиться, сервер ответит 403 — как у задач в ADR-0151.
- Передача бота сразу на клиенте прежнего владельца не отражается (`mine` обновляется на READY) — та же оговорка.
- Миграций нет: первичный ключ `bots` и `workspace_members`. Интеграционный тест `TestBotOwnerEditsBotMessages`.
