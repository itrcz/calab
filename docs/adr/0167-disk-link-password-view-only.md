# ADR-0167: Диск — пароль и «Без скачивания» на публичной ссылке (2026-11-10)

**Статус: принято.** Дополняет [ADR-0094](0094-disk.md) §3 и [ADR-0165](0165-disk-folder-public-link.md)
(«Вне объёма: пароль на ссылку, „Без скачивания“»). Задача CBF-168.

## Контекст
Публичная ссылка на файл или папку открывает содержимое любому, у кого есть код. Код — 32 случайных
байта, угадать его нельзя, но он утекает: пересылка письма, скриншот чата, история браузера чужого
компьютера. Владельцам нужны два привычных по Google Drive / Яндекс Диску переключателя: пароль
поверх кода и «только просмотр» — показать подрядчику материалы, не раздавая файлы.

## Решение
1. **Модель.** В `disk_links` три поля (миграция 00151): `password_hash` (argon2id тем же
   `auth.HashPassword`, что пароли входа; NULL — без пароля), `password_version` и `view_only`.
   Пароль никогда не покидает сервер: клиент видит только `DiskLink.has_password`. Длина 4–128
   символов.
2. **Управление** — `PATCH /api/disk/items/{id}/link` (`UpdateDiskLinkRequest {optional password,
   optional view_only}`; `password = ""` снимает пароль) и поля `password` / `view_only` в
   `POST …/link` для новой ссылки (живая ссылка на `POST` не меняется). Права те же, что у самой
   ссылки: владелец элемента, «Управление» (ADR-0161) или `DISK_MANAGE`; «Правка» — 403. Боты —
   теми же маршрутами (`bot-sdk`: `disk.link.on(…, {password, viewOnly})`, `disk.link.update`).
   История: `link_password_on` (`after.changed` — пароль заменён), `link_password_off`,
   `link_view_only_on` / `link_view_only_off`, автор — кто нажал; сам пароль в журнал не пишется.
3. **Разблокировка.** Пока посетитель не ввёл пароль, `GET /api/public/disk/{code}` отвечает только
   `PublicDiskFile.locked = true` — ни имени, ни вида, ни размера, ни списка; остальные анонимные
   маршруты (`/content`, `/thumbnail`, `/items`, `/items/{id}/content|thumbnail`, `/archive`,
   `/office`) — `403 ERROR_CODE_LINK_PASSWORD_REQUIRED`. `POST …/unlock {password}` проверяет пароль
   (argon2id, сравнение за постоянное время) и ставит cookie `calab_dl`: `HttpOnly`, `Secure`,
   `SameSite=Lax`, `Path=/api/public/disk/{code}`, 12 ч (не дольше срока ссылки). Значение —
   `exp ‖ HMAC-SHA256/128(ключ, link.id ‖ password_version ‖ exp ‖ code)`, ключ выведен из
   `JWT_SECRET` (`calab/disk-link-unlock/v1`). Серверного состояния у разблокировки нет.
4. **Что гасит разблокировку.** Смена или снятие пароля и повторное включение ссылки увеличивают
   `password_version` (повторное включение ещё и меняет код) — старые cookie перестают сходиться;
   выключенная или истёкшая ссылка отвечает 404 раньше проверки. Cookie ссылки A к ссылке B не
   подходит: в подписи её id и код.
5. **Перебор.** Неверный и пустой пароль — один и тот же ответ (403 с тем же кодом, без cookie).
   До хеширования тратятся два лимита Redis: на IP (5 сразу, 5 в минуту) и на ссылку (20 сразу,
   10 в минуту, с любых IP). Лимит на ссылку позволяет злоумышленнику на время заблокировать ввод
   пароля честному посетителю — сознательная цена: перебор с ботнета хуже. Хеширование ограничено
   общими слотами argon2 (`auth`), сервер не уходит в CPU.
6. **«Без скачивания».** Страница не показывает «Скачать», «Скачать всё» и кнопку скачивания в
   просмотрщиках. Сервер: `/archive` (и `?check=1`) — 403; `content` отдаёт только то, что страница
   смотрит в браузере (картинки, видео, аудио, PDF, текст/код/Markdown/CSV — по MIME и расширению,
   как `diskPreview` клиента), с `Content-Disposition: inline` (CSP `sandbox`, `nosniff` остаются),
   остальное — 403; документы Office открываются в Document Server с `permissions.download / print /
   copy = false`. Файл без просмотрщика — карточка «Просмотр недоступен» без кнопки. Миниатюры
   отдаются как раньше. Пароль и «Без скачивания» независимы и работают для файлов и папок.

## Последствия
- **«Без скачивания» — барьер, а не защита.** Всё, что показано в браузере, можно сохранить:
  байты картинки, видео и PDF приходят посетителю целиком, текст копируется, экран снимается;
  встроенный просмотрщик PDF браузера сам предлагает «Скачать»; конфигурация Document Server
  содержит подписанный URL файла (живёт минуты, ADR-0143). Подсказка переключателя говорит это
  владельцу прямо. Защита от утечки — пароль, срок ссылки и её выключение.
- Пароль защищает от утечки кода, но не от того, кому пароль сообщили: тот может переслать и его.
  Смена пароля — способ отозвать доступ у всех, кто уже открыл ссылку, без смены кода.
- Cookie на путь ссылки: другой код в том же браузере требует своего пароля; страница `/d/{code}`
  и API на одном origin, `SameSite=Lax` достаточно. Истекшая разблокировка во время просмотра
  возвращает страницу к форме пароля.
- Документ Office, открытый до смены пароля, можно дочитать (конфигурация живёт 12 ч, ADR-0165).
