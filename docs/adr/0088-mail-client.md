# ADR-0088: Почтовый клиент в десктопном приложении (2026-10-12)

## Контекст
Владелец, 12.10: «добавить раздел почта, который открывает интерфейс а-ля Apple Mail: добавить почту,
проверять, отправлять, получать уведомления». На вопрос, где держать почту — на сервере Calab или на
компьютере, — решение: «а мы не можем тянуть почту на компьютер локальный? по сути так же делает
клиент почтовый» → «давай сделаем только в приложении, просто иконку с почтой доступную». Добавление
аккаунта: «вводишь почтовый адрес и пароль, он лезет в DNS, если не находит — пробует smtp. imap.
mail., если не получается — тогда только спрашивать адреса, чтобы в один клик всё настраивалось»;
«ещё можно из DNS брать MX-запись и по ней понять, какие адреса использовать».

Исходящая транзакционная почта Calab (коды, приглашения, встречи) — [ADR-0023](0023-email.md), пакет
`internal/mail` на сервере; к этому решению она отношения не имеет. Прецедент внешнего аккаунта с
паролем — CalDAV ([ADR-0041](0041-calendar-freebusy.md)), но там хранение серверное.

## Решение

### 1. Почта живёт на компьютере пользователя, сервер Calab о ней не знает
Как Apple Mail и Thunderbird: десктопное приложение само ходит по IMAP/SMTP, держит локальную базу и
кэш тел писем. На сервер Calab не попадают ни пароли, ни письма, ни метаданные; протокол `proto/` не
меняется; тарифных лимитов нет. Следствие, принятое владельцем: **раздел «Почта» есть только в
десктопном приложении**. Веб-клиент и телефон (WebView веб-клиента, ADR-0067) раздел не показывают
вовсе — браузер не умеет IMAP; уведомления о письмах приходят, пока Calab запущен (он живёт в трее).
Серверный режим для веба/телефона, если понадобится, — отдельный ADR; экраны при этом не меняются,
меняется только реализация контракта §7.

### 2. Отдельный процесс движка, не main и не renderer
Правило «ничего тяжёлого в main» (docs/01) сохраняется: движок почты — **`utilityProcess`** Electron
(`apps/desktop/src/main/mail/engine.ts`, отдельный вход сборки main в `electron.vite.config.ts`),
Node 24 (Electron 44). Библиотеки — чистый JS, нативных модулей нет: `imapflow` (IMAP, IDLE,
CONDSTORE/QRESYNC), `nodemailer` (SMTP), `mailparser` (разбор MIME); база — встроенный **`node:sqlite`**
(проверено: Electron 44.5.1 → Node 24.21.0, `require('node:sqlite')` доступен). Зависимости идут в
`dependencies` (внешние для бандла main, как `electron-log`; `scripts/check-main-bundle.mjs` проверяет
и вход движка). Main запускает движок при старте, если есть хоть один аккаунт (иначе — при первом
добавлении), перезапускает при падении с экспоненциальной паузой, убивает при выходе. Renderer как и
прежде без Node: с движком говорит через узкий IPC preload'а (§7); main — тонкий посредник
(`MessagePort`), плюс то, что умеет только main: `safeStorage`, уведомления, протокол вложений, guard
навигации (§10).

### 3. Хранение
- `userData/mail/accounts.bin` — список аккаунтов с настройками IMAP/SMTP и паролями, целиком
  зашифрован `safeStorage` (Keychain / DPAPI / libsecret), как refresh-токен в `main/auth.ts`.
  Пароли расшифровывает main и передаёт движку в память при старте; в SQLite паролей нет.
- `userData/mail/<accountId>/mail.sqlite` (WAL): `folders` (path, роль, uidvalidity, highestmodseq,
  счётчики), `messages` (uid, message_id, thread_id, from/to/cc, subject, snippet ≤ 200 символов,
  date, флаги, размер, has_attachments, body_state), `attachments` (имя, mime, размер, cid),
  `outgoing` (очередь отправки), `drafts`; FTS5 по теме, отправителю, сниппету и тексту загруженных тел.
- Тела и вложения — файлы `userData/mail/<accountId>/blobs/<sha256>`; грузятся при открытии письма
  (и заранее для последних 50 во «Входящих»), кэш ограничен (по умолчанию 1 ГБ на аккаунт, настройка),
  вытеснение LRU — IMAP остаётся источником правды, тело всегда можно перечитать.
- Начальная синхронизация: заголовки за 90 дней во всех папках; дальше — всё новое. В конце списка —
  «Загрузить более ранние» (ещё 90 дней). Удаление аккаунта стирает его каталог целиком.

### 4. Добавление аккаунта — одно поле адреса и пароль
Форма: «Почта», «Пароль», кнопка «Добавить». Движок подбирает настройки по цепочке, останавливаясь на
первом успехе (каждый шаг ≤ 3 с, пробы параллельно, общий предел 10 с):
1. **Таблица известных провайдеров** по домену адреса: Gmail (`gmail.com`, `googlemail.com`), Яндекс
   (`yandex.*`, `ya.ru`), Mail.ru (`mail.ru`, `bk.ru`, `list.ru`, `inbox.ru`, `internet.ru`), iCloud
   (`icloud.com`, `me.com`, `mac.com`), Microsoft (`outlook.*`, `hotmail.*`, `live.*`).
2. **MX-запись домена** (владелец, 12.10): хост MX выдаёт провайдера для своего домена на чужой почте —
   `aspmx.l.google.com` → Google Workspace, `mx.yandex.net` → Яндекс 360, `emx.mail.ru` → Mail.ru для
   бизнеса, `*.mail.protection.outlook.com` → Microsoft 365. Если MX не из таблицы, сам хост MX и
   домен MX добавляются в кандидаты шага 5 (у маленьких серверов `mail.example.com` — и MX, и IMAP, и SMTP).
3. **Autoconfig**: `https://autoconfig.<domain>/mail/config-v1.1.xml`,
   `https://<domain>/.well-known/autoconfig/mail/config-v1.1.xml`, затем база Thunderbird
   `https://autoconfig.thunderbird.net/v1.1/<domain>`.
4. **DNS SRV** (RFC 6186): `_imaps._tcp`, `_imap._tcp`, `_submissions._tcp`, `_submission._tcp`.
5. **Проба хостов**: `imap.<d>`, `mail.<d>`, `<d>` и кандидаты из MX на 993 (TLS), затем 143 (STARTTLS);
   `smtp.<d>`, `mail.<d>`, кандидаты из MX на 465 (TLS), затем 587 (STARTTLS). Проба = TCP + TLS +
   приветствие сервера.
6. Только если ничего не подошло — ручная форма (IMAP-хост/порт/шифрование, SMTP-хост/порт/шифрование,
   логин), заполненная лучшими догадками.

Найденные настройки проверяются реальным входом в IMAP и SMTP; успех — аккаунт сохранён и
синхронизация началась, ошибка входа — «Неверный пароль» с подсказкой провайдера: у Gmail, Яндекса,
Mail.ru и iCloud нужен **пароль приложения** (ссылка на инструкцию провайдера). Microsoft (личные и
365) с паролем не работает вовсе — требуется OAuth2; в v1 форма честно пишет «Пока не поддерживается».
Только TLS/STARTTLS, сертификат проверяется строго; открытого текста нет. Логин по умолчанию — полный
адрес; autoconfig может задать `%EMAILLOCALPART%`.

**Недоверенный сертификат — доверие с первого раза (12.10, владелец: «если можно давай максимально
скипнем проверки, чтобы всё работало даже с self-signed»; повод — часы Mac на ~6 ч позади, свежий
сертификат Let's Encrypt «ещё не действует»).** Проверку не отключаем молча (пароль IMAP/SMTP ушёл бы
любому MITM). Ошибка `TLS` несёт сертификат (`MailError.cert`: хост, порт, SHA-256, subject, issuer,
даты, причина `self_signed | untrusted | expired | not_yet_valid | name_mismatch | other`); форма
показывает его словами (для дат — с текущим UTC-временем компьютера и советом проверить часы) и
кнопку «Доверять этому серверу и подключиться»: отпечаток закрепляется за сервером
(`MailServerSettings.pinnedCert`, IMAP и SMTP отдельно, хранится в `accounts.bin`). Соединение с
закреплённым сервером принимает ровно этот сертификат либо любой нормально проверяемый; другой
недоверенный — `TLS` с `reason: 'changed'`, ящик в `error` до подтверждения нового в настройках.
Решение принимается до первой команды (LOGIN/AUTH не уходят). Discovery считает такой сервер
найденным и помечает `certIssue`, чтобы спросить до отправки пароля.

### 5. Синхронизация
Одно IMAP-соединение на аккаунт: IDLE на «Входящих», остальные папки — опрос раз в 5 минут и при
открытии папки; CONDSTORE/QRESYNC, где сервер умеет, иначе сравнение UID и флагов; смена
`UIDVALIDITY` — полная пересборка папки. Роли папок — по `SPECIAL-USE`, иначе по именам (в т. ч.
русские и `[Gmail]/…`). Цепочки — по `References`/`In-Reply-To`, запасной ключ — нормализованная тема
в пределах 7 дней. Ошибки сети — пауза с экспоненциальным ростом до 15 мин; ошибка входа — состояние
`auth_failed`, строка аккаунта просит пароль. Действия пользователя (прочитано, флаг, архив, в
корзину, перенос) применяются локально сразу и ставятся в очередь к IMAP; при сбое откатываются с
тостом.

### 6. Отправка
Через SMTP пользователя (не через outbox Calab). Письмо — `text/plain` + `text/html` (из текста
редактора, цитата оригинала blockquote'ом), вложения ≤ 25 МБ суммарно, `In-Reply-To`/`References` у
ответов, `Message-ID` свой. Очередь `outgoing` с повторами (1 мин → 1 ч, до 24 ч), папка «Исходящие» в
переключателе показывает ожидающие и упавшие (повторить/удалить). После отправки — `APPEND` в
«Отправленные», если провайдер не делает это сам (Gmail делает). Ответ ставит флаг `\Answered`.
Черновики в v1 — локальные (`drafts`), в IMAP не синхронизируются.

### 7. Контракт renderer ↔ движок
`apps/desktop/src/shared/mail.ts` — типы и единственный источник правды для обеих сторон; preload
открывает пространство `mail` (есть только в Electron: `Platform.mail?: MailApi`, веб — `undefined`).
Запросы (`id, method, params` → ответ или ошибка `{code, message}`):
- `accounts.list / discover(email) / add({email, password, settings?}) / update / remove / setPassword`;
- `folders.list(accountId)`;
- `messages.list({ scope: accountId | 'all', folder: role | folderId, before?, limit, unreadOnly? })` —
  заголовки цепочек страницами по курсору; `messages.get(id)` — письмо с телом (грузит при необходимости);
  `messages.thread(threadId)`; `messages.setFlags / move / archive / trash / delete / loadOlder`;
- `compose.send(draft)`, `drafts.save / list / remove`, `outgoing.retry / remove`;
- `search(query, { scope })`; `sync.now(accountId?)`; `settings.get / set` (картинки из сети, подпись,
  уведомления, размер кэша).
События движок → renderer одним каналом `mail:event`, склеенные (≤ 1 на папку в 250 мс):
`account_state`, `folders`, `messages_added`, `messages_changed`, `messages_removed`, `outgoing`,
`new_mail` (для уведомления). Вложения и `cid:`-картинки — через привилегированный протокол
`calaba-mail://attachment/<messageId>/<attachmentId>` (main, как `calaba-api://`), только
`image/*` для inline, остальное — скачивание штатным `downloads.ts` (карантин / Mark-of-the-Web).
Для разработки и e2e — mock-реализация `MailApi` в renderer (`CALABA_MAIL_MOCK=1`) с фикстурами.

### 8. Клиент (docs/08, ориентир — Apple Mail)
Раздел **«Почта»** на рейле (ADR-0074) после «Доски», личный (без пространства), только Electron;
бейдж — непрочитанное всех аккаунтов (примитив). Раскладка — существующая оболочка:
- **Колонка списка**: в шапке переключатель ящика «Входящие ⌄» (лист: «Все входящие»; по аккаунту —
  Входящие, Отмеченные, Отправленные, Черновики, Исходящие, Архив, Спам, Корзина, прочие папки, у
  каждой свой счётчик), «+» — новое письмо, поиск, фильтр «Непрочитанные». Строка цепочки: отправитель
  полужирным, время справа, тема, две строки превью, точка непрочитанного слева, флажок, скрепка,
  число писем в цепочке. Виртуализация (`react-virtuoso`), строки в `memo`, свайпы не нужны.
- **Центр**: цепочка — письма друг под другом, свёрнутые кроме последнего; у письма шапка (аватар-
  инициалы, от/кому/дата, «Подробнее» раскрывает все адреса), панель действий (Ответить, Ответить всем,
  Переслать, Архив, В корзину, Флаг, Прочитано/Не прочитано, Переместить), тело в sandboxed iframe
  (§10), под ним полоса вложений (иконка/превью, имя, размер; картинки — в существующий лайтбокс).
  Картинки из сети выключены: полоса «Картинки скрыты · Показать · Всегда для этого отправителя».
- **Новое письмо / ответ**: шит в центре (как лист встречи), поля «Кому» (чипы, автодополнение из
  истории адресов этого аккаунта и участников пространств), «Копия/Скрытая», «Тема», от какого аккаунта,
  текст с автоссылками, цитата оригинала, вложения (кнопка и перетаскивание), подпись из настроек.
  Отправить — `⌘↩`. Закрытие с текстом — «Сохранить черновик?». Форматирование (жирный, списки) — v2.
- **Пустое состояние** раздела — карточка «Добавьте почту» с формой §4 и строкой про пароль приложения.
- **Настройки → «Почта»**: аккаунты (добавить, удалить, сменить пароль, имя отправителя, подпись),
  «Уведомлять о новых письмах», «Показывать картинки из сети», размер кэша и «Очистить».
- **Уведомления**: `new_mail` во «Входящих» (не спам, аккаунт уже синхронизирован) → системное
  уведомление «Имя отправителя · Тема» по тем же правилам, что сообщения (DND, окно в фокусе на этом
  письме — не показывать); клик открывает письмо; диплинк `calab://mail/<accountId>/<messageId>`.
- Хоткеи как в Apple Mail: `⌘R` ответить, `⇧⌘R` всем, `⇧⌘F` переслать, `⌘⌫` в корзину, `⇧⌘U`
  непрочитанное, `↑/↓` по списку, `⌘N` новое письмо.
- Правая панель в разделе не используется.

### 9. Производительность (CLAUDE.md, docs/14)
Без звонка ≤ 1 % CPU: в простое движок держит один IDLE-сокет и ничего не делает; в renderer таймеров
нет, обновления приходят событиями. iframe с HTML — только у открытого письма; санитизированный HTML
кэшируется по id; в сторе — страница заголовков и открытая цепочка, не весь ящик. Событие о письме
перерисовывает одну строку и бейдж (`tools/perf-call.ts`). Память движка ≤ 60 МБ на двух аккаунтах.
Замер `tools/energy-bench.py` до/после — в отчёте агента.

### 10. Безопасность — второе ревью обязательно (CLAUDE.md п. 5)
- Пароли — только в main/движке (§3); renderer видит пароль один раз в форме при добавлении.
- HTML письма: DOMPurify (строгий профиль: без скриптов, форм, `<iframe>`/`<object>`, внешних CSS,
  `url()` в стилях — только с разрешёнными картинками), в `<iframe sandbox>` без `allow-scripts` и
  `allow-same-origin`, `srcdoc` с `<meta http-equiv="Content-Security-Policy" content="default-src
  'none'; img-src data: calaba-mail: [https: при разрешении]; style-src 'unsafe-inline'">`.
  Удалённые картинки блокируются по умолчанию (трекеры); разрешение — на письмо или отправителя.
- Ссылки: клик в iframe вызывает навигацию фрейма → main перехватывает `will-frame-navigate`, отменяет
  и открывает `http(s)` в системном браузере (существующая политика URL); прочие схемы — запрет.
  `mailto:` — новое письмо в Calab.
- Вложения: только через §7 с проверкой id; скачивание — штатное (карантин). `calaba-mail://` отдаёт
  inline только `image/*`.
- Сеть: только TLS/STARTTLS со строгой проверкой сертификата (исключение — сертификат, закреплённый
  пользователем по отпечатку, §4; проверка в обёртке `tls.connect` до любой команды, без закрепления
  опции остаются строгими); хосты autoconfig/ISPDB берутся только
  с `https`; приватные адреса (10/8, 192.168/16, localhost) допускаются — это почтовый клиент, а не
  сервер, SSRF здесь не возникает.
- Движок — отдельный процесс без доступа к сессии Calab и его API.

### 11. Сборка и тесты
- `dependencies` += `imapflow`, `nodemailer`, `mailparser`; `third-party-notices` их подхватывает.
  `electron-builder.yml` без изменений (нет нативных модулей).
- Unit: таблица провайдеров и разбор MX/SRV/autoconfig; сверка папки по UID/флагам и `UIDVALIDITY`;
  цепочки; очередь отправки — на фейковом транспорте. Интеграционный (opt-in `CALABA_MAIL_IT=1`):
  GreenMail (`greenmail/standalone`, IMAP+SMTP) профилем `mail` в dev-compose. UI — typecheck/lint/unit
  и один QA-проход скриншотами (визуальные прогоны выключены, CLAUDE.md).

### 12. Ссылка «Добавить почту в Calab» (владелец, 12.10)
Владелец: «`https://calab.io/?mail={base64 email:password}` — диплинк, или в вебе открывается и там
кнопка добавить почту в Calab диплинком». Назначение — выдать сотруднику ящик одним кликом.
- **Формат:** `base64url("email:password")` (пароль может содержать `:` — разделитель первый). Пароль
  необязателен: `base64url("email")` открывает форму с адресом, пароль вводится руками.
- **Только фрагмент** (владелец, 12.10: «в целом только `#mail=` поддерживать, чтобы безопасно было»).
  Единственный вид — `https://calab.io/#mail=<payload>`: фрагмент браузер не отправляет на сервер, его
  нет в логах Caddy, у прокси и у ботов превью ссылок. `?mail=` не принимается: payload в query
  игнорируется, карточка не показывается — чтобы такие ссылки не расходились.
- **Лендинг (`apps/landing`):** клиентский скрипт читает только `#mail=`, декодирует и проверяет синтаксис
  адреса, показывает карточку «Добавить почту <адрес> в Calab» (пароль не показывается и никуда не
  отправляется) с кнопкой → `calab://mail/<payload>` (владелец, 12.10: «зарегистрируем диплинк типа `calab://mail/base64`»; тот же payload путём — у кастомной схемы сервера нет, логов нет); ниже —
  «Нет Calab? Скачать» существующими ссылками релизов для платформы. На телефоне кнопки нет: «Почта
  доступна в приложении для компьютера». Битый payload — карточка «Ссылка повреждена».
- **Приложение:** `main/deeplink.ts` принимает `calab://mail/<payload>` (и алиас `calaba://`) и, как SSO-тикеты, **не
  логирует** сырой URL; renderer открывает раздел «Почта» с формой §4, заполненной адресом и паролем
  (пароль скрыт), фокус на «Добавить» — один клик, автоматически аккаунт не создаётся. Ссылку можно слать и без лендинга — прямо `calab://mail/<payload>`; лендинг нужен там, где кастомная схема некликабельна. Если такой
  адрес уже добавлен — «Эта почта уже подключена».
- **Риск, принятый владельцем:** payload — пароль в открытом виде (base64 — не шифрование); кто
  получил ссылку, получил ящик. Ссылку передавать лично (DM в Calab), не публиковать; на Windows/Linux
  аргумент командной строки с диплинком на миг виден в списке процессов. Шифровать нечем — у ссылки
  нет сервера-посредника; это осознанный компромисс ради «в один клик».

## Альтернативы
- **Серверная синхронизация в Go** (`internal/mailbox`, IMAP IDLE с лизингом в Redis, тела в blob):
  даёт почту в вебе и на телефоне и push без запущенного десктопа, но сервер хранит чужие пароли и
  письма (ответственность для SaaS), диск, квоты, ретенция, лизинг. Отклонено владельцем, 12.10.
- **IMAP прямо в main-процессе**: проще, но нарушает «ничего тяжёлого в main» — разбор MIME и синк
  блокировали бы окно.
- **`better-sqlite3`** вместо `node:sqlite`: второй нативный модуль в сборке (Windows собирается в
  Linux-Docker — пришлось бы тянуть prebuilds); встроенный модуль снимает вопрос.
- **Скрипт в iframe для перехвата ссылок** (postMessage): работает, но требует `allow-scripts` в
  письме; `will-frame-navigate` в main даёт то же без скриптов.
