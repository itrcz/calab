# ADR-0151: Задачи, созданные ботом, — авторские для его владельца (2026-10-30)

**Статус: принято.** Дополняет [ADR-0031](0031-bots.md) (бот — пользователь, `bots.owner_user_id`),
[ADR-0106](0106-bot-acts-as-owner.md) и [ADR-0109](0109-bot-rights-like-people.md) (бот сам за себя — со своими
правами), [ADR-0115](0115-board-create-only.md) (автор — основание «только создавать»). Задача доски #136.

## Контекст
Владелец: «если бот пользователя создал задачу, у пользователя должно быть право её редактировать». Бот,
работающий сам за себя (без `Calab-On-Behalf`), записывает автором себя (`tasks.created_by` = бот). Правила по
авторству — правка своей задачи с `CREATE_TASKS`, архив/восстановление своей, «только создавать» (видеть свои
карточки) — сравнивали только `created_by`, поэтому владелец бота без `EDIT_TASKS` свою же (по сути) задачу не
мог ни править, ни видеть на закрытой доске.

## Решение
1. **Одно определение автора.** `perm.TaskAuthor(createdBy, botOwner, user)`: пользователь создал задачу **или**
   он текущий владелец бота, который её создал (`bots.owner_user_id` для `created_by`; `nil` — не бот или бот
   удалён). TS-зеркало — `isTaskAuthor(task, me, myBots)` в `packages/protocol`; `taskPermissions` получает
   `myBots` четвёртым аргументом. Через эту функцию идут **все** правила по авторству:
   - `perm.TaskBits` (автор для «только создавать») — `taskBitsOf`, `visibleTasks`, комната задачи
     (`perm.Resolver.taskRoom`), список «приглашённых» задач (`ListInvitedTasks`, `invitedCond` — видимость в
     списках, поиске и «Мои задачи»), gateway (`invitesOf`, `ListWorkspaceTaskInvitees`);
   - `canEdit` (правка полей, описания, статуса, исполнителей и всего, что за `requireEdit`) — «автор или
     исполнитель с `CREATE_TASKS`»;
   - `setArchived` (архив/восстановление) — «`EDIT_TASKS` или автор с `CREATE_TASKS`».
   **Только в домашнем пространстве бота** (`bots.workspace_id` = пространство доски): там владелец управляет
   ботом (токен, удаление — `homeBot`). Бот, добавленный в чужое пространство его администраторами, автором
   своего владельца там не делает: владелец мог уйти из домашнего пространства (ботом тогда управляют его
   `MANAGE_BOTS`), а в чужом остаться. Клиент этого не различает (`my_bot_ids` без пространства) — кнопка
   там может появиться, сервер ответит 403.
   Доступ к доске владелец получает только свой: нужен тот же `CREATE_TASKS` (и `VIEW_BOARD` или
   «только создавать»), что и автору-человеку; приватная доска без доступа — ничего нового.
2. **Владелец — текущий, без хранения.** Владелец не копируется в задачу: он резолвится в том же запросе, что и
   задача (`taskCols`: скалярный подзапрос по первичному ключу `bots`; `GetTaskRoomRef`: `LEFT JOIN bots`;
   условия списков — `EXISTS` по `bots`). Лишнего запроса на задачу в списках нет. Сменится владелец — права
   переходят к новому; бот удалён (строки `bots` нет) — прав нет; владелец ушёл из пространства или отключён —
   у него нет доступа к доске, значит, и прав.
3. **Клиент.** `READY.my_bot_ids` — id ботов получателя (`ListOwnedBotIDs`), дальше `BOT_CREATE`/`BOT_UPDATE`
   с `owner_user_id` = я добавляют бота (`stores/bots.mine`). Клиент передаёт этот набор в `taskPermissions` и
   `mayEditTask`/`mayArchiveTask`/`mayRestoreTask` (`taskAuthor` в `lib/boards/access.ts`) — кнопки правки
   появляются там же, где сервер их разрешит. Поле на `Task` («владелец бота-автора») отвергнуто: задачи
   рассылаются всему пространству, а владелец бота виден только ему и `MANAGE_BOTS` (публичная карточка
   владельца не показывает). Удалённый бот остаётся в наборе до следующего READY (`BOT_DELETE` не отличает
   удаление от выхода из пространства и владельцу не приходит) — кнопка может появиться, сервер ответит 403.
4. **Gateway.** Состояние пространства хранит владельцев ботов-участников (`ListWorkspaceMemberRoles`:
   `bot_owner`; `BOT_CREATE`/`BOT_UPDATE` обновляют, `BOT_DELETE` забывает — fail closed до перезагрузки
   состояния). Автор задачи бота для «только создавать» — его владелец; сам бот, как и раньше, не считается.
5. **Только права.** Ленты и уведомления не меняются: «Мои задачи → Созданные» — по `created_by`; обязательное
   уведомление об итоге согласования и получатель «создатель» в автоматизациях — тот, кто в `created_by`
   (бот получает своё через события). Подписка автора при создании — как раньше (подписан бот).
6. **Не про задачи.** Авторство сообщений и комментариев (правка своего сообщения), представлений, правил,
   форм и т. п. — по-прежнему по их `created_by`/`author_id`: владелец не правит сообщения своего бота.
   *Изменено [ADR-0162](0162-bot-owner-edits-bot-messages.md): правку сообщений бота владелец получил по тому же
   правилу.*

## Безопасность
Владелец и так управляет ботом (выпускает себе токен — ADR-0031/0106), так что правка задач бота через свою
сессию не даёт ему ничего, чего он не может через бота; при этом права проверяются по **своим** битам владельца
на доске, а не по битам бота. `MANAGE_BOTS`-администратор, не владеющий ботом, авторских прав не получает.
Ни бот, ни гость автором через это правило не становятся (боты и гости не бывают «только создавать»).
