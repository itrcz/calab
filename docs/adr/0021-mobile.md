# ADR-0021: Мобильные клиенты и адаптация (2026-09-26)

> Этап B заменён [ADR-0067](0067-phone-shared-web-host.md) (2026-10-02): телефон — общий веб-клиент в оболочке Expo + WebView, без второго UI на React Native.

## Контекст
Владелец: нужна мобильная адаптация и клиенты iOS/Android на React Native с автообновлением при старте.

## Решение (в два этапа)
**Этап A — мобильный веб (сейчас, после P0-багов).** Веб-клиент (`app.calab.ru`) адаптируется под ≤ 768 px: одна колонка, сайдбар/список участников — выдвижные панели, нижняя панель голоса как остров, композер над клавиатурой, PWA-манифест (иконка на экран). Голос и чат работают в мобильном Safari/Chrome; PTT — удержание кнопки. Это даёт телефонам рабочий клиент без магазинов и покрывает 80 % сценариев.

**Этап B — приложение на Expo/React Native (`apps/mobile`).**
- Общий код: `packages/protocol` (protobuf-es, `computePermissions`) как есть; из `apps/desktop/src/renderer` выделяется `packages/core` — stores (Zustand), gateway-клиент, сервисы без DOM/Electron (`platform` уже абстрагирован: electron|web → добавляется `native`).
- Медиа: `@livekit/react-native` (+ `@livekit/react-native-webrtc`): те же правила — Opus 32k DTX, remote-звук через нативный аудиотрек (без WebAudio), AEC системный; экран — только просмотр стримов; камера — публикация VP8/H264 (AV1 на мобильных не кодируем).
- **Автообновление при старте:** `expo-updates` с собственным сервером обновлений на `releases.calab.ru/mobile/` (протокол Expo Updates, статические манифесты + бандлы, подпись code-signing). JS/asset-обновления применяются при старте; нативные изменения — через магазины (TestFlight/App Store, Google Play; Android дополнительно APK на сайте).
- Push: APNs/FCM через сервер (таблица `devices`, отправка упоминаний/DM/звонков); фоновой звук; CallKit/ConnectionService — v2.
- Дистрибуция и подпись: EAS Build или локальный Xcode/Gradle в CI; сертификаты — в `.env`/GitHub secrets как у десктопа.

## Последствия
- Этап A — 1–2 дня одним агентом, без изменений сервера.
- Этап B — отдельный план в `docs/09` (раздел «Mobile»), стартует после DM и стабилизации 0.2.x; первым делом — выделение `packages/core` (это же упростит десктоп и веб).
