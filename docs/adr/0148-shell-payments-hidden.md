# ADR-0148: Платёжный UI скрыт в любой нативной оболочке (iOS и Android)

Дата: 2026-10-30. Статус: **принято**. Уточняет ADR-0087 §10 для Android (пока не решён сторный биллинг).

## Контекст

ADR-0087 §10 скрывал покупки, цены, действия с деньгами и ссылки «оплатить в вебе» только в оболочке iOS (правило App Store против платежей мимо IAP); Android-оболочка (`apps/mobile`, ADR-0067) вела себя как браузер — платежи были видны. Владелец, 30.10: «платёжный UI должен быть скрыт в любой нативной оболочке телефона, и в Android тоже».

## Решение

1. **Правило.** `planOffersAllowed()` (`services/plan.ts`) теперь `false` для любой нативной оболочки (`nativeShell() !== null`), не только для iOS. Новый хелпер `inNativeShell()` в `platform/nativeShell.ts` заменяет `iosNativeShell()`; детектор (`detectNativeShell`, fail closed на iOS) не меняется.
2. **UI — тот же, что был у iOS.** Для держателя `BILLING_VIEW` — кабинет только для чтения (суммы видны), нейтральная строка «Управление оплатой доступно в веб-версии и на компьютере» без ссылки и кнопки; покупки, цены, смена тарифа, автопополнение, карты, плательщик, шаг тарифа и ссылки «оплатить в вебе» — нигде.
3. **Не меняется.** Браузеры на телефоне (Safari, Chrome без признака оболочки — `SHELL_UA_MARKER`/бридж), PWA и десктоп — как раньше, с покупками. Сервер не трогаем — права и так проверяются там же.

## Последствия

- Снимок `billing-cabinet-ios` остаётся как есть; добавлен `billing-cabinet-android` (тот же экран, UA-маркер + Android, без бриджа).
- Если для Android появится сторный биллинг (Google Play), это новое ADR, а не откат этого.
