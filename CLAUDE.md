# Calaba — заметки для Claude Code

Voice-first десктоп-мессенджер для команды (Electron + LiveKit + Go + Postgres). Общение с пользователем — по-русски; код, комментарии в коде и коммиты — по-английски.

## Обязательно прочитать перед изменениями
- `docs/01-architecture.md` — компоненты и потоки
- `docs/02-media.md` — аудио/видео; **правила эхоподавления нарушать нельзя** (remote-звук только через `<audio>`, никакого WebAudio на выходе)
- `docs/04-data-model.md` — права: единственная функция `computePermissions` в `packages/protocol`
- `docs/08-design.md` — дизайн-система и UX-правила; любой UI-код им соответствует
- `docs/adr/` — почему принято каждое решение; менять решение = новый ADR
- `docs/06-deployment.md` — стенд, прод в Kubernetes, runbook релиза; `docs/11-maintenance.md` — устройство CI, зависимости, PR

## Структура
- `apps/desktop` — Electron (main / preload / renderer). Медиа-логика в renderer. Renderer без Node.
- `apps/mobile` — оболочка телефона (ADR-0067): Expo + один WebView с веб-клиентом, без своих экранов; origin из env; статус — `docs/mobile/shared-web-status.md`.
- `apps/server` — Go: REST + WS gateway (`net/http`, `coder/websocket`, `pgx`+`sqlc`, `rueidis`). Stateless, состояние в Postgres/Redis. Лёгкость и низкая задержка — приоритет: без тяжёлых фреймворков и ORM.
- `proto/` — protobuf-контракт (buf), источник правды. `make gen` → Go в `apps/server/gen`, TS в `packages/protocol/src/gen`. **Сгенерированный код коммитим**; после правки `.proto` — `make gen` и коммит вместе (CI проверяет дрейф). В комментариях `.proto` не делать строк, начинающихся с пробелов — gofmt разных версий Go форматирует их по-разному, и `gen` дрейфует.
- `packages/protocol` — TS-сторона контракта + `computePermissions` (дублируется в Go `internal/perm`, общие тест-векторы в `proto/testdata`).
- `infra/docker` — compose (стенд и dev), Caddy (`caddy/`, caddy-l4), LiveKit, `release.sh`/`deploy.sh` — стенд, **не прод** (прод — k8s, см. docs/06).

## Правила кода
- TS strict на клиенте. Go — `gofmt`, `go vet`, `golangci-lint` **только через `make lint` в `apps/server`** (конфиг `.golangci.yml` в корне, `--build-tags integration`, версия как в CI v2.14.0); прямой `golangci-lint run ./pkg/...` пропускает правила и даёт ложный «0 issues». Типы контракта только из сгенерированного кода.
- Все права проверяются на сервере; LiveKit-grant повторяет права. Клиент лишь скрывает UI.
- Конфигурация — только через env. Никаких хостов/секретов в коде.
- **Производительность — приоритет продукта** (у сотрудников слабые компьютеры). Бюджет CPU: без звонка ≤ 1 %, в голосе без речи ≤ 5 %, при просмотре стрима — не больше декодера; скрытое окно не декодирует видео и не крутит таймеры/анимации. **CSS `backdrop-filter`/стекло запрещены** везде; единственное стекло — нативное `vibrancy` окна Electron на macOS за рейлом/колонкой/тайтлбаром (ADR-0075). Бесконечные анимации — только лоадеры; тяжёлые эффекты — только на видимом и с `prefers-reduced-motion`/режимом «слабый компьютер». Бюджет и замеры — `docs/14-energy.md`, `tools/energy-bench.py`; оптимизация — с цифрами до/после.
- **Ререндеры под контролем**: Zustand-селекторы возвращают примитив или `useShallow`-срез по id, не объект целиком; строки списков (лента, участники, комнаты) в `memo`, колбэки стабильные, пропсы без новых объектов на рендер; часто меняющееся (уровни, speaking, таймеры, typing, статистика) — в листовых компонентах со своим подписчиком, стор обновляется по порогу, не на каждый тик; контексты без изменчивых значений. Перед мержем фичи в голосе/ленте/панелях: `CALABA_REACT_PROFILING=1` + `tools/perf-call.ts` (docs/14 «Ререндеры в звонке») — событие не должно перерисовывать больше строк, чем затрагивает.
- Приоритет — качество и продуманность, не скорость. Перед нетривиальным решением — короткое обоснование, при смене архитектуры — ADR.
- Minor-замечания ревью — строкой в `docs/09-ui-backlog.md` (UI) или `docs/12-tech-backlog.md` (сервер/инфра), не новой задачей. Docs правим только при изменении поведения/контракта; TESTING.md — сценарий ≤ 15 строк.

## Машина владельца и стенд
- **Диск**: `apps/desktop/dist` (~1.5 ГБ) после локальной сборки удалять; при свободном месте < 15 ГБ — `docker builder prune -af`, `docker image prune -af --filter until=24h`, `go clean -cache`. Релизный агент проверяет место перед релизом.
- **Локальный Caddy** — только с тестовыми хостами (`*.test`/`localhost`) и `local_certs`/`auto_https off`; с боевыми `APP_HOST/RELEASES_HOST/LANDING_HOST` не поднимать — сожжёт лимиты Let's Encrypt боевого домена.
- **Стенд `root@141.105.69.177`** — compose: Caddy/LiveKit/SIP/egress/Valkey; API и БД прода там нет (прод — k8s). Чужая GPU-задача (python/ffmpeg/chromium, порты 8000–8400, 9100, 9400) — **не трогать**. Наши порты: 80, 443, 7881, 7882.
- Секреты (`.env`, prod-env, ключи Stripe/Tochka/Cloudflare, токен бота) — `/Users/mac/Documents/Calaba/.env` и рядом, gitignored, не печатать в отчётах.

## Работа с агентами
Лид (Fable) — архитектура, спорные решения, ревью дизайна, мерж и теги. Код пишут субагенты. Дорого и медленно: долгоживущие агенты с огромным контекстом, общее дерево, ревью, порождающие ревью, повторные прогоны. Поэтому:
1. **Свежий агент на задачу**: точная постановка (что, где, какие docs/ADR, критерий готовности) → отчёт → агент завершён. Если задача выросла — новая задача, не переписка. Долгоживущий только один: инфра/стенд.
2. **Модель по задаче**: небольшие фичи и фиксы — Sonnet 5.5; серьёзные (протокол, `computePermissions`, auth, токены, CI с секретами, отладка без ясной причины, фичи с новыми сущностями в нескольких слоях) и ревью — Opus 5.5; механика (changelog, docs по готовому тексту, триаж PR, QA скриншотами, прогон тестов) — Sonnet/Haiku.
3. **Параллельно ≤ 3 агентов** с непересекающимися путями, без «вспомогательных» агентов (владелец, 15.10: сессии должны быть дешевле). Каждый — в своём `git worktree` и ветке со своими портами/БД (`CALABA_VISUAL_MOCK_PORT`, `MOCK_LIVEKIT_ROOM_PREFIX`, `TEST_REDIS_URL` — свой номер DB, `TEST_PG_URL` — своя база). Worktree агента создаётся от `main`: если работа идёт в фичевой ветке — в брифе велеть сначала `git merge <ветка>`. Не удалять worktree агента, пока ему могли отправить сообщение после завершения.
4. **Агент коммитит сам** на своей ветке (мелко, по-английски, с чек-листом проверок). Лид только мержит (rebase/ff на main) и тегирует; файлы за агентов не редактирует.
5. **Отчёт — один раз, ≤ 15 строк**: что сделано · файлы · какие проверки прошли (команды и цифры) · риски/что не проверено. Ожидания (CI, деплой) — внутри одного хода (`gh run watch`, `until … sleep`); никаких промежуточных «жду CI», никаких дублей через SendMessage.
6. **Одно ревью на изменение — всегда одно, второго нет** (владелец, 03.11: второе всегда повторяет первое, это лишние время и токены). Ревьюер — Opus 5.5; для сложного (security-пути, протокол, `computePermissions`, auth/токены) — Fable. Фиксим только blocker/major; ревьюер сам правит очевидное и коммитит.
7. **Тесты экономно**: в цикле — typecheck/lint/unit + интеграционный тест пакета, который трогали (`go test -tags integration ./internal/<pkg>`); полный интеграционный набор — один раз перед мержем ветки. e2e-web — только `app.calab.io` (chromium); `meet.gptunnel.ru` — smoke.
8. **CI на main — зелёный всегда**. Агенты перед коммитом гоняют то же, что CI: `make gen` + `git diff --exit-code`, `make lint`, `go test -race`, `pnpm -s typecheck/lint/test`. Лид после пуша в main ждёт `ci.yml` (`gh run watch` фоново) и не мержит следующее, пока красный; красный CI — блокер раньше любой фичи. Пуши только `docs/**`/`*.md` CI не запускают. Устройство `ci.yml` (шарды, `reuse` для тегов) — docs/11.
9. **Релиз важнее полировки**: во время релиза на main — только блокеры релиза. Лид не раскручивает хвосты из отчётов: новая задача — только блокер релиза или пункт утверждённого бэклога.
10. **На «глянь PR»** — либо решить и смержить, либо оставить ревью-комментарий на GitHub; не спрашивать. Разумные продуктовые дефолты (биллинг и т. п.) — выбирать и делать, спрашивать только про деньги/юридику/необратимое.

## Релиз
Runbook — docs/06 «Релиз с 3.0». Коротко: релизный агент (Sonnet) пишет в CHANGELOG `### Коротко` (3–7 строк простым языком, бот публикует только его) и `python3 tools/usage-stats.py` → `docs/13-usage.md`; тег `vX` на SHA, уже зелёном на main (тогда `ci` тега ~1 мин); `release.yml` (установщики, S3-фид, GitHub Release — черновик) и `images.yml` (образы → GitHub Deployment `calab-prod`, кластер забирает сам); дождаться `https://app.calab.io/api/version`; `gh release edit vX --draft=false --latest`; анонс. **Если всё зелёное — релиз без подтверждения владельца** (14.10); спрашивать только при сбое. `release.sh deploy/backup` — старый стенд, для прода не использовать.

## Визуальные тесты
- **Не запускаем** (ни nightly — `visual-nightly` выключен, ни локальные `e2e:visual*`): перф, рефакторинг, логика, сервер — только typecheck/lint/unit. Включить nightly — только по слову владельца.
- **Любая видимая правка интерфейса** (добавили кнопку, поле, пункт меню, колонку, блок, либо поменяли вёрстку, текст или поведение элемента на экране) — проверяем затронутые экраны визуально: прогон per-screen спеки и осмотр PNG на обрезки, перекрытия, пустые и загрузочные состояния, контраст, светлую и тёмную тему, телефон. Если спеки на экран нет — пишем её (шагом в существующий тест экрана через `checkpoint`), а не оставляем непроверенным. Перед мержем фичи с интерфейсом визуальная проверка обязательна.
- **Исключение — новый экран/диалог/виджет**: per-screen спека и один прогон `pnpm -F @calaba/desktop e2e:visual -g "<screen>"` (dark-960 + iPhone 14; светлая тема — для ключевого диалога); агент смотрит каждый PNG один раз и перечисляет проблемы. Новый сценарий — шагом в существующий тест экрана (`checkpoint`), не отдельным тестом.
- Полных прогонов и массовой перезаписи эталонов на машине владельца нет. Устаревшие локальные эталоны остаются устаревшими до следующей правки экрана. Полная матрица — только nightly на Linux (`CALABA_VISUAL_ALL=1`).
- Один тестовый Electron за раз (`CALABA_VISUAL_WORKERS=1`); два агента не гоняют e2e параллельно. `/Applications/Calab.app` владельца — не тестовый экземпляр. Тесты — с `--mute-audio`.

## Команды
```
pnpm install && make gen
pnpm infra:dev                          # postgres, valkey, mailpit, livekit --dev (compose.dev.yml)
cd apps/server && go run ./cmd/server   # или make dev-server
pnpm dev:desktop
make test                               # go test + pnpm test
```
