# ADR-0064: Формы приёма задач для досок (2026-10-04)

Статус: реализовано; локальная приёмка и полный CI прошли на `dc967918`.
Независимые security/protocol review и выпуск ожидаются; [evidence](../qa/board-forms/README.md).
База: `3eeb3ca3` (2.3.0), уточняет ADR-0042, ADR-0054/0055/0056, ADR-0058/0060/0063.
Версия контракта: 4 (расширенные типы и независимый источник заголовка). Реализация следует этому контракту; изменение решения требует правки ADR.

## Требование владельца

В меню ⋯ доски — «Формы»: создание, редактирование, копирование внешней ссылки,
минималистичная публичная страница; приватный доступ выбранным пользователям.
Настраиваемые поля, подписи, подсказки, обязательность; статус и приоритет новой задачи
задаются отдельно каждой форме. Из редактора можно заполнить тестовую форму без записи.
Бот может создавать, редактировать и заполнять формы через API. Удалённая форма недоступна.
Тарифы: Free — нет; Team — 5 форм на доску; Business — 20; выше — без ограничения количества.
Обязательны реальные сквозные проверки человека и бота, скриншоты и следующий релиз.

## Решение лида: границы первой версии

- Одна форма создаёт одну обычную задачу. Отдельной очереди заявок нет.
- Поля: короткий текст, длинный текст, email, телефон, ссылка, число, дата, выбор одного или нескольких вариантов,
  флажок. Любое поле можно изменить или удалить; минимум одно поле. Источник заголовка
  выбирается отдельно, по умолчанию — название формы. Ответы становятся разделами описания.
- До 30 полей, до 30 вариантов в поле выбора, стабильные UUID полей. Перестановка не
  меняет идентификаторы. Название формы до 100, вступление до 2000, подпись до 100,
  подсказка/placeholder до 500, ответ до 2000, суммарное описание до 20000 символов.
  Текст трактуется как текст: HTML не исполняется, упоминания не создают уведомлений.
- Без вложений, ветвления, платежей, автоматических исполнителей и кастомного CSS.
- Приватный список — существующие участники пространства, включая ботов; до 100.
  Право видеть доску не требуется: форма намеренно предоставляет только приём задачи.
  Добавление в список не выдаёт членства или прав доски. Ушедший/заблокированный
  участник теряет доступ даже при оставшемся UUID в списке.
- Внешние люди без аккаунта заполняют публичные формы. Для приватной формы нужен вход
  в выбранный аккаунт; SSO/reauth и suspension соблюдаются как для пространства.
- Публичный ingress считается public capability: в SSO-enforced пространстве закрыт
  согласно ADR-0054. Это не исключение из Identity 2.0; редактор объясняет ограничение.

## Поле телефона (дополнение владельца, 2026-10-04)

Требование владельца: добавить телефон как отдельный тип поля.
Решение лида: новый enum PHONE = 8, существующие номера не меняются; миграция не нужна.
Телефон хранится строкой, с сохранением форматирования и ведущих нулей. После обрезки
краевых пробелов — не больше 64 символов, от 7 до 15 ASCII-цифр; разрешены пробел,
скобки, дефис, точка и один необязательный `+` только в начале. Это проверка формата,
не существования номера; страна не угадывается, код страны не дописывается.
Пустой необязательный телефон допустим. Добавочные номера и короткие сервисные номера
в первой версии не поддерживаются. UI использует общий Input с type=tel, autocomplete=tel,
maxLength=64 без маски страны. Preview и публичный/ботовый POST вызывают одну валидацию;
ошибка — 422 с UUID поля, без создания задачи. SDK использует расширенный generated enum.
Приёмка: национальный/международный формат и ведущий ноль проходят; буквы, неверный плюс,
слишком мало/много цифр, слишком длинная строка — отказ; обязательность и пустое значение;
реальные preview и bot submit сохраняют телефон в описании задачи. URL/multiselect описаны ниже и входят в эту реализацию.

## Расширенные типы и заголовок (решение лида по разрешению владельца)

- URL = 9: строка до 2000 символов, абсолютный HTTP/HTTPS URL с непустым hostname,
  без userinfo, пробелов и управляющих символов. Никакого fetch/unfurl при отправке.
- MULTISELECT = 10: те же 1..30 уникальных вариантов, что SELECT. Ответ — новое
  `BoardFormAnswer.values` (repeated string, номер 3); `value` должен быть пустым.
  Другие типы принимают только `value`, непустой `values` отклоняется. Неизвестные и
  повторные варианты, >30 ответов — 422. Required требует хотя бы один вариант.
  Для nonce-хэша values сортируются; в описании перечисляются в порядке настроек поля.
  UI — группа подписанных checkbox, без нестандартного селектора и без маски строки JSON.
- `title_field_id` необязателен; разрешено любое одиночное поле кроме CHECKBOX/MULTISELECT.
  Если источник не выбран или ответ пустой, заголовок = название формы. Непустой ответ
  преобразуется в одну строку и обрезается до 200 Unicode-символов; полный ответ всегда
  сохраняется в описании. При удалении источника или смене его типа на CHECKBOX/MULTISELECT
  редактор сбрасывает источник на название формы. API отклоняет несуществующий/неподходящий id.
  Ни тип первого поля, ни обязательность поля-источника больше не фиксируются.
- Старые определения и клиенты с прежними типами продолжают работать. Новые enum/values
  аддитивны, миграции нет. Старые SDK нужно обновить для новых типов. Серверное развертывание
  предшествует публикации клиента; общий контракт принадлежит лиду этой реализации.
- Приёмка: все типы required/optional; invalid URL/phone/multiselect не создают задачи;
  nonce не зависит от порядка выбранных вариантов; preview без записи; публичная и бот-
  отправка, формат/полнота описания, заголовок/fallback/truncation; изменение первого поля.

## Модель и инварианты

`board_forms`: id UUIDv7, board_id FK CASCADE, code (32 случайных байта base64url,
UNIQUE), definition jsonb (proto BoardFormDefinition), revision int >= 1,
created_by FK SET NULL, created_at, updated_at. В definition: title, description,
fields[], title_field_id, is_private, allowed_user_ids[], status_id, priority.

`board_form_submissions`: id UUIDv7 (квитанция), form_id FK CASCADE, nonce UUID,
request_hash bytea, actor_id nullable FK SET NULL, task_id nullable FK SET NULL,
created_at; UNIQUE(form_id, nonce). Ответы хранятся в задаче, второй копии нет.
Сохраняются название формы и подписи/ответы на момент отправки в журнале/описании.

- Статус обязан принадлежать этой доске. Его удаление переносит задачи существующим
  способом, но формы не перенастраивает молча: отправка даёт FORM_TARGET_UNAVAILABLE,
  редактор требует выбрать новый статус. При отключённом PRIORITY ненулевой приоритет
  формы даёт FEATURE_DISABLED, без молчаливой потери настройки.
- Архив доски, suspension, удаление формы, недоступный тариф блокируют отправку.
- Управление — VIEW_BOARD + MANAGE_BOARD, включая ботов. Просмотр формы отправителем
  не раскрывает board_id, status_id, priority, ACL, автора, статистику или другие формы.
- Создание/изменение конфигурации, отправка, удаление сериализуются блокировкой строки
  доски, затем формы. Число форм проверяется под тем же lock: параллельные POST не
  превышают тариф. Права и состояние проверяются в транзакции записи.
- DELETE удаляет конфигурацию и квитанции; освобождает место тарифа. Задачи остаются.
  Новый code никогда не переиспользуется; запрос после завершившегося DELETE — 404.
  Уже начатая отправка либо коммитится до удаления, либо отвергается; половины задачи нет.
- Для приватной отправки actual actor = проверенный пользователь/бот; для анонимной —
  NULL, без фиктивного авторства владельца. Отправителю не выдаётся доступ к задаче,
  не создаётся подписка или членство. Ответ не содержит ID/ключ задачи.
- Задача, скрытая комната, номер, журнал, квитанция и outbox вебхука создаются одной
  транзакцией. TASK_CREATE публикуется после commit с обычной фильтрацией прав доски.
  Общий лимит 5000 живых задач сохраняется.
- Обычные автоматизации доски (ADR-0060) выполняются для созданной задачи в той же
  транзакции и могут изменить назначенные формой статус/приоритет. Настройки формы
  задают начальные значения; права действий правил остаются контрактом автоматизаций.
  Preview не запускает правила. Повтор nonce не создаёт новых запусков.

## API / proto

Источник контракта — `proto/calaba/v1/board_forms.proto`; Go/TS generated коммитятся.
Все JSON-сообщения — protojson, неизвестные поля отклоняются.

Управление (обычная authenticated middleware, identity scopeBoard, botAllow):

- GET /api/boards/{id}/forms → ListBoardFormsResponse.
- POST /api/boards/{id}/forms {definition} → BoardFormResponse, 201.
- PUT /api/boards/{id}/forms/{fid} {definition, revision} → BoardFormResponse.
  Полная замена; конфликт revision → 409 FORM_CHANGED, без last-write-wins.
- DELETE /api/boards/{id}/forms/{fid} → 204.
- POST /api/boards/{id}/forms/preview {definition, answers[]} → FormSubmissionResponse
  {preview:true}. Валидирует текущий несохранённый draft и ответы, никогда не вызывает
  создание задачи, публикацию событий, outbox, подписки или выделение номера.

Отправитель (два транспорта с общими обработчиками валидации):

- GET /api/public/forms/{code} и POST /api/public/forms/{code}/submissions — без аккаунта,
  только публичные формы; переданный Authorization не превращает запрос в приватный.
- GET /api/forms/{code} и POST /api/forms/{code}/submissions — authenticated,
  botAllow, новый identity scopeForm с резолвом workspace по code; private ACL + членство.
- GET → PublicBoardFormResponse {title, description, fields[], revision}; никогда ACL
  или настройки маршрутизации. Для private на публичном GET — 401 без полей;
  неверный code/недоступная доска/неразрешённый аккаунт — 404 без метаданных.
- POST {revision, nonce, answers[{field_id,value}]} → {receipt_id,preview:false}, 201;
  повтор идентичного запроса → прежняя квитанция, 200. Nonce обязателен, генерируется
  до первой отправки; повтор с другим содержимым/актором → 409 NONCE_CONFLICT.
  Проверка текущего доступа предшествует выдаче старой квитанции.
- revision устарел → 409 FORM_CHANGED; клиент предлагает перечитать форму, сохраняет
  введённое локально и не отправляет автоматически по изменённым условиям.
- 422 с field для пустого обязательного, неверного типа, неизвестного/повторного поля,
  отсутствующего варианта или превышенного размера. Флажок: true/false, required требует true.
  Число — конечное десятичное, дата — существующая YYYY-MM-DD, email — адрес без display name.
- 409 PLAN_LIMIT / FORM_TARGET_UNAVAILABLE / FEATURE_DISABLED / BOARD_TASK_LIMIT;
  429 с Retry-After. Никаких задач/номеров/вебхуков при любой ошибке.

## Безопасность, сроки и тарифы

- Все ответы ingress: Cache-Control: no-store; страница: noindex, Referrer-Policy:
  no-referrer. Code — capability, не UUID; в аналитике/ошибках/скриншотах боевых
  пользователей не сохранять ссылки и ответы. БД хранит code для копирования менеджером.
- Публичные GET: 30/min/IP; отправки: 5/min/IP и 30/min/form. Приватные отправки:
  10/min/user и общий лимит формы. Общий body limit 128 KiB. Лимиты разделяются в Redis,
  ошибки Redis — fail closed. Honeypot/CAPTCHA не заменяет эти ограничения; CAPTCHA вне v1.
- Бот использует существующий Bearer bot token и тот же API. Отозванный token, потеря
  членства/прав, suspension, ACL и тариф проверяются сервером. SDK: forms.list/create/
  update/delete/get/submit/preview с generated request/response типами.
- Поля PlanLimits: board_forms_disabled и board_forms_per_board (0 = без лимита).
  Free true/0, Team false/5, Business false/20, custom/on-prem — конфигурация,
  default custom/on-prem false/0. Env/admin поддерживают оба поля.
- При downgrade на Free формы сохраняются: менеджер может прочитать и удалить, но
  редактирование, preview и приём остановлены. При Business → Team с >5 формами
  существующие работают, новые запрещены до освобождения места. Поднятие тарифа
  возобновляет работу. Пауза тарифа не считается удалением.
- Автоматического срока жизни ссылки нет. Немедленный отзыв — DELETE или private ACL;
  public→private отзывает анонимный доступ и для уже открытой страницы при POST.
- Identity admission применяется на commit, включая свежие policy/member/session
  состояния. Public capability policy и suspension проверяются под workspace locks;
  публичная транзакция не получает синтетическую user identity.

## Интерфейс

В ⋯ доски пункт «Формы» для менеджера. Лист: название, публичная/приватная, «Копировать
ссылку», редактирование, удаление с подтверждением «Ссылка перестанет работать.
Созданные задачи сохранятся». Счётчик 3/5 или 3/20; Free — объяснение Team.

Редактор: название и описание; последовательность карточек полей (тип, подпись,
подсказка, placeholder, обязательность, варианты, вверх/вниз, удалить); настройка
заголовка задачи; ниже статус/приоритет и доступ с поиском участников, включая ботов.
«Сохранить», «Копировать ссылку» (для сохранённой формы), «Протестировать».
Несохранённые изменения защищены подтверждением закрытия. В preview явная плашка
«Тестовый режим — задача не будет создана», после отправки «Проверка пройдена».

Публичная страница: одна колонка до 640 px, название, вступление, подписи над полями,
подсказки под ними, один акцентный submit; общие токены light/dark, мобильный 390 px,
клавиатура и доступные label/error associations. После успеха «Ответ отправлен» без
ссылки на задачу. Для удалённой — «Форма недоступна». Отдельный маршрут /f/{code}
до обычной оболочки, без загрузки досок или списка участников для анонимного человека.
Локализация ru/en/es/zh-CN, без хардкода русского в UI.

## Миграция и совместимость

PlanLimits использует новые номера 33/34 (32 занят автоматизациями).
00067 добавляет две таблицы и индексы, не переписывает tasks. Откат удаляет только
формы/квитанции, сохраняет задачи. PG17 acceptance; совместимость PG18 сохраняется.
Старые клиенты продолжают видеть обычные задачи. Новые REST маршруты классифицируются
в bot/identity registries и покрываются exhaustive tests. Новых прав/gateway events нет:
управление формами обновляет локальный список после мутации; revision защищает другие окна.

## Критерии приёмки и выпуска

1. Unit: определения/типы ответов/лимиты/маппинг описания/идемпотентность.
2. PG17 integration: CRUD; атомарная задача+комната+журнал+outbox; выбранные статус/
   приоритет; 5/20/unlimited/Free; concurrency quota, delete/submit, duplicate nonce.
3. Матрица доступа: anonymous/private, чужой аккаунт, ACL revoke, lost membership,
   board rights, archived/purged board, suspension, revoked bot, SSO policy transition,
   legacy session/recovery principal; проверка обходов через все новые маршруты.
4. Preview: счётчики tasks/rooms/activity/outbox/submissions и next_number неизменны.
5. Browser Playwright на реальном локальном сервере/PG17: создать форму в UI, заполнить
   публично, увидеть задачу в целевой колонке/приоритете; private deny/allow; delete;
   preview без задачи; скриншоты новых экранов desktop 960×600/mobile 390, без visual suites.
6. Реальный bot token: создать/изменить/read/submit, проверить задачу человеком; отказ
   без MANAGE_BOARD и для приватной формы без ACL. SDK соответствующий сценарий.
7. make gen и drift, make lint из корня, typecheck/unit, целевые race/integration,
   один полный integration PG17 перед merge. Два независимых security/protocol review
   на итоговом SHA обязательны для выпуска; запрет запуска агентов сам по себе не отменяет gate.
8. Релиз — актуальный docs/06 runbook, зелёный CI, changelog/usage (ограничения Codex
   stats честно), tag/release/assets/feeds, API/web smoke, обязательный анонс ботом.

## Порядок реализации

Лид самостоятельно: контракт/миграция/generated → сервер/identity/тарифы → UI/SDK/docs →
приёмка/review → релиз. Разрешённые пути: proto, server, protocol, bot-sdk, desktop,
docs/TESTING/CHANGELOG и релизные версии. Не затрагивать чужую ветку лендинга, медиа,
SSO-контракты или production до завершения acceptance. Открытых вопросов, блокирующих
первую реализацию, нет; новые продукты (файлы/ветвление/срок ссылки) — отдельное решение.
