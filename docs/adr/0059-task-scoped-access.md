# ADR-0059: Доступ по карточке — исполнители и согласующие без доступа к доске (2026-10-03)

**Статус: принято; правило о закрытых досках (§1 «не закрытая», §3 `!Restricted`, «Не входит») заменено
[ADR-0076](0076-task-watchers.md)** — карточку открывает и на закрытой доске; к исполнителям и согласующим
добавлены наблюдатели (третье основание). Уточняет ADR-0042 §1–2 (кого можно назначить исполнителем), ADR-0049 §1 (кого — согласующим),
ADR-0048 (закрытые доски). Новых событий шлюза и новых битов прав нет; `computePermissions` / `ComputeBoard` не меняются.
Релиз — следующий минорный после 2.1.0. Миграция — только если понадобится индекс (см. §3), номер **00060**.

## Контекст
Владелец (03.10): «доска доступна всем, у кого есть права, но мы можем добавить в исполнители или согласующие
людей других — и тогда у них тоже видна доска должна быть, но они должны видеть только те карточки, в которые
их позвали». Уточнения: такой человек работает на своей карточке как обычный исполнитель (согласующий —
смотрит, комментирует, голосует); звать можно любых участников пространства, кроме гостей; на закрытых
(`restricted`) досках это не работает — закрытая значит закрытая.

Сегодня (`boards.assigneesIn`, `approversIn`) исполнителем и согласующим можно назначить только того, кто уже
видит доску; видимость доски — всё или ничего по биту `VIEW_BOARD` (`perm.ComputeBoard`).

## Решение

### 1. Понятие: участник доски «по карточкам» (task-scoped)
Участник пространства **видит доску по карточкам**, если одновременно:
- у него нет `VIEW_BOARD` на доске (`ComputeBoard` = 0);
- он не гость и не бот (боту по-прежнему нужен `VIEW_BOARD` — ADR-0042 §2, ADR-0031);
- доска живая (`archived_at IS NULL`) и **не закрытая** (`restricted = false`; приватная — можно);
- он исполнитель (`task_assignees`) **или** согласующий (`task_approvers`) хотя бы одной **живой** задачи доски
  (`tasks.archived_at IS NULL`).

Такой участник видит доску (имя, ключ, статусы, лейбли, вехи, общие виды, категорию, фичи) и **только свои
карточки** — те, где он исполнитель или согласующий. Остальных задач, журнала доски, настроек, доступа, вебхука
для него не существует. Сняли с карточки — карточка исчезает; сняли с последней (или задачу архивировали, доску
закрыли/архивировали, участника сделали гостем) — исчезает доска. Это производное состояние: **новых таблиц нет**,
источник правды — `task_assignees` / `task_approvers` / `boards.restricted`.

Почему не новый бит `VIEW_OWN_TASKS` в `board_permissions`: бит — свойство роли/пользователя на доске целиком, а
здесь право даёт сама карточка и исчезает вместе с ней; переопределение пришлось бы ставить и снимать при каждом
назначении и считать ссылки. Производное состояние проще и не расходится с данными.

### 2. Права на карточке — одна функция, зеркально Go/TS
```
perm.TaskBits(acc BoardAccess, assignee, approver bool) Bits        // Go, internal/perm/board.go
taskPermissions(board: Board, task: Task, me: string): PermissionBits  // TS, packages/protocol/permissions.ts
```
- `acc.Bits` содержит `VIEW_BOARD` → `acc.Bits` (ничего не меняется для обычных зрителей);
- иначе `acc.TaskScoped && assignee` → `VIEW_BOARD | CREATE_TASKS` — ровно то, что сегодня даёт участнику
  «править свои и назначенные на себя» (`canEdit`): статус, поля, чек-листы, исполнители, согласующие, комментарии;
  **создать задачу на доске нельзя** — `createTask` проверяет биты доски, а они 0;
- иначе `acc.TaskScoped && approver` → `VIEW_BOARD` — смотреть, комментировать, подписываться, голосовать
  (голосование по ADR-0049 — только сам согласующий, пока видит задачу);
- иначе `0` (404, как для невидимой задачи).
Комната задачи: `perm.TaskRoom(TaskBits(...), …)` / `taskRoomPermissions(taskPermissions(...), …)` — те же правила,
`EDIT_TASKS` у такого участника не бывает, модерации чужих комментариев нет. Unit-тесты на обе стороны (таблица
случаев одинаковая); в `proto/testdata/permissions.json` векторы не добавляем — `computePermissions` не тронут.

### 3. Сервер
**Резолвер** (`perm/board_resolver.go`): `BoardAccess` получает `TaskScoped bool`. `GetBoardAccess` возвращает ещё
один столбец `invited` — `EXISTS (живая задача доски, где user — исполнитель или согласующий)`; `TaskScoped =
invited && Bits = 0 && !Restricted && Role ≠ guest && !Archived`. Индексы: `task_assignees(user_id)` есть;
для `task_approvers` есть только partial `(user_id) WHERE state = 'pending'` — нужен полный `task_approvers(user_id)`
(миграция 00060). `GetTaskRoomRef` расширяется параметром `user_id` и флагами `assignee`/`approver`; `taskRoom`
считает биты через `TaskBits`.

**Доступ к доске** (`boards.board()`): для `TaskScoped` возвращает `BoardAccess` с `Bits = 0` вместо 404. Каждый
обработчик `/api/boards/{id}/*` явно решает: разрешено по карточкам или требует бит. Таблица:
| Маршрут | По карточкам |
|---|---|
| `GET /workspaces/{id}/boards`, READY `boards` (`Snapshot`), `GET /boards/{id}`, unfurl `/b/` | да: доска с `task_scoped = true`, `permissions = 0`, общие и личные виды |
| `GET /boards/{id}/tasks` | да, `WHERE` + `EXISTS (исполнитель или согласующий = me)`; фильтры, курсор, `updated_after` работают; `archived=1` — пусто (приглашение считается только на живых задачах) |
| `POST /boards/{id}/upload` | да (вложение в описание своей карточки; квота пространства) |
| виды `POST/PATCH/DELETE /boards/{id}/views` | нет — виды только читать (403, как участнику без прав) |
| задачи `POST`, статусы, лейблы, вехи, порядок, настройки, `permissions`, `webhook`, `activity`, архив/purge, категории | нет — как участнику с нулевыми битами (403); по карточкам ничего не открывается |
| `/api/tasks/{id}/*`, `/api/t/{KEY-N}`, unfurl `/t/`, `/api/checklists/*`, `/api/checklist-items/*` | `taskAccess` → `acc.Bits = TaskBits(acc, assignee, approver)`; 0 → 404. Дальше — существующие правила (`canEdit`, `requireEdit`, approval gate, чек-листы «как поля задачи») без изменений. Связи — вторая задача должна быть видна (иначе 404); подзадача — через `createTask`, запрещено; перенос на другую доску — `MANAGE_BOARD`, запрещено |
| `GET /me/tasks`, `GET /workspaces/{id}/tasks/search`, `OpenTasksOf` (профиль участника, ADR-0051) | `VisibleBoards` возвращает и доски по карточкам отдельным множеством; SQL: `board_id = ANY(full) OR (board_id = ANY(scoped) AND EXISTS invited(viewer))` — в профиле чужие задачи с доски по карточкам видны, только если смотрящий тоже позван |

**Назначение**: `assigneesIn` / `approversIn` — пользователь-человек проходит, если он участник пространства, не
гость, и (`VIEW_BOARD` **или** доска не `restricted`); бот — только с `VIEW_BOARD` (как сейчас). Ошибка на закрытой
доске — прежняя `the user does not see this board`. Снять исполнителя с карточки может тот, кто её правит, —
в том числе сам участник по карточкам (`CREATE_TASKS` + назначен), после чего он её теряет; это ожидаемо.

**Уведомления** (`notify.sees`): фильтр «видит доску» становится «видит задачу» (`TaskBits ≠ 0`) — иначе
`ASSIGNED` / `APPROVAL_REQUESTED` позванному со стороны не дойдёт. Напоминания согласующим (ADR-0049 §5) — так же.
Вебхук доски и боты — без изменений (события по доске, не по зрителю).

**Шлюз** (`gateway/boards.go`). Состояние доски дополняется: `invited map[task][]user` (исполнители ∪
согласующие живых задач живых досок; загрузка — новый запрос `ListWorkspaceTaskInvitees`, обновление — из `Task` в
`TaskCreate/TaskUpdate`, снятие — `TaskDelete`) и счётчик `scoped map[user]map[board]int`. `boardVisible(bid, u)` =
`boardBits.Has(VIEW_BOARD) || (scoped[u][bid] > 0 && доска не restricted && член не гость)`. Маршрутизация:
- события задачи (`TaskCreate/Update/Delete`, `TaskActivity`, `TaskChecklistUpdate/Delete` — у всех есть `task_id`) —
  зрителям доски **и** приглашённым этой задачи; сообщения комнаты задачи — через `taskRoomBits` с `TaskBits`;
- `TaskUpdate` — переход на получателя, как `boardTransition`: был приглашён и перестал (без `VIEW_BOARD`) →
  ему `TaskDelete` (`purged = false`); не был и стал → `TaskCreate`; счётчик `scoped` 0→1 даёт перед этим
  `BoardCreate` (`task_scoped = true`, `permissions = 0`), 1→0 — после `BoardDelete`;
- события доски (`BoardCreate/Update/Delete`, категории) — зрителям и участникам по карточкам; `forRecipient`
  ставит им `task_scoped = true`, `permissions = 0`; `BoardUpdate` с `restricted = true` или архив → им `BoardDelete`
  (через `boardVisible` в `boardTransition`); `WORKSPACE_MEMBER_UPDATE` (стал гостем) — тот же пересчёт, что сегодня
  для `VIEW_BOARD`.
Unit-тесты переходов в `gateway` (таблица: назначили / сняли / последняя карточка / доску закрыли).

### 4. Контракт (`boards.proto`)
- `Board`: `bool task_scoped = 28;` — «смотрящий видит доску по карточкам: только задачи, где он исполнитель или
  согласующий; `permissions = 0`». Комментарии у `TaskAssigneeInput.user_id` и `SetTaskApproversRequest.user_ids`:
  «участник пространства, не гость; на закрытой доске — только видящий её; бот — только видящий доску».
- Новых событий и полей задачи нет: клиент считает права карточки `taskPermissions(board, task, me)` — поэтому
  события остаются общими для всех получателей (`newScopedEnc`), без персональных полей.
- `make gen`, сгенерированное — в коммит.

### 5. Клиент (`features/boards`, `docs/08` «Доски»)
- Список досок: доска по карточкам — с бейджем-чипом «Только мои карточки» (muted, 20 px, подсказка «Вы видите
  только задачи, где вы исполнитель или согласующий»), сортировка общая. Стор: `Board.taskScoped` — `permissions = 0`
  **не** означает «скрыть»; хелпер `boardVisible(b)` в `lib/boards`.
- Канбан / список / таймлайн — обычные, с тем, что пришло; скрыты «+ Задача», `C`, настройки, доступ, правка видов,
  массовые действия, перенос; фильтр и виды работают. Пустая доска по карточкам не бывает — она исчезает.
- Панель задачи — права из `taskPermissions`; исполнитель правит как обычно, согласующий — только голос и комментарии.
- Пикер исполнителей и согласующих: все участники, кроме гостей (ботов — только видящих доску); у тех, кто не видит
  доску (`computeMemberBoardPermissions` по стору), подпись «увидит только эту карточку»; на закрытой доске — только
  видящие, остальные disabled с подсказкой «закрытая доска».
- `TASK_DELETE` без `purged` на карточке, которой больше нет в сторе зрителя, — убрать из стора и закрыть панель, если
  открыта (сейчас архив делает то же). `BOARD_DELETE` — закрыть доску, если открыта.
- i18n: ru/en/es/zh-CN. Визуальные прогоны не запускаем (правило 30.09); QA-проход скриншотами по новому бейджу,
  пикеру и доске по карточкам.

## Не входит
- Позвать на карточку гостя или бота без доступа к доске; наблюдатели («watchers») без роли; доступ по карточкам на
  закрытых досках (владелец: закрытая значит закрытая). Шаблон «согласующие по умолчанию» — ADR-0049 бэклог.

## Последствия
- Назначить можно почти любого коллегу — пикер больше не молчит; у позванного появляется доска с одной карточкой.
- Приватная доска раскрывает позванному своё имя, ключ, статусы, лейблы и вехи — осознанно, назначение делает тот, кто
  правит задачу. На закрытых досках — ничего нового.
- Ещё один столбец в `GetBoardAccess` (EXISTS по индексу) и маленькая карта приглашённых в состоянии шлюза.
