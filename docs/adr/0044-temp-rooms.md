# ADR-0044. Временные комнаты

Статус: принято (2026-09-30); сервер реализован 30.09 (миграция 00048), отклонения и контракт — в конце. Владелец, 30.09: «функционал временных комнат: + → ввести название и
срок жизни, можно кинуть встречу в календарь; ссылка сразу появляется; на комнате меню — скопировать
ссылку или удалить (полностью не удаляется, остаётся в архиве, но подключиться уже нельзя); права
выдавать мемберам по умолчанию, но можно отключить в пространстве; иконки для таких комнат особые;
она может быть приватной — только для выбранных людей и тех, кто зашёл по ссылке, — или публичной
для всех участников пространства; этим закрываем функционал Zoom, чтобы менеджеры продаж быстро
собирались с клиентами».

## Контекст

Голосовые комнаты создаёт `MANAGE_ROOM` (ADR-0008), и они живут вечно. Для разовых созвонов
(«обсудить релиз», «созвон с подрядчиком») сотрудники просят у админа комнату, а потом она висит
в списке. Нужна комната «на час / на день», которую может завести любой участник, с готовой
ссылкой для приглашённых (в том числе гостей, ADR-0016/0040) и которая сама исчезает. Главный
сценарий — замена Zoom: менеджер продаж создаёт комнату, кидает ссылку клиенту (гость, без
регистрации), разговор идёт в нашем голосе/видео, остальное пространство комнату не видит.

## Решение

### Модель
- `rooms.expires_at timestamptz` (NULL = постоянная) и `rooms.created_by uuid` (миграция `00048`; `00047` — ADR-0043).
  Временная комната — обычная `type='voice'` с `expires_at`; `is_temp` в контракте = `expires_at != null`.
  Ничего нового в `type`: голос, чат, стрим, записи, права комнаты — как у голосовой.
- Архив — существующий `rooms.archived_at`. Архивная комната: не в списке, не в LiveKit, ссылки
  отозваны, `VIEW_ROOM` только на чтение истории (см. «Архив»).
- Право `PERMISSION_CREATE_TEMP_ROOMS = 8388608` (1 << 23), уровень пространства. **Участнику
  по умолчанию — да** (в дефолтных битах роли Member; миграция добавляет бит существующим ролям
  Member/Moderator, гостям — никогда). Отключить в пространстве = снять бит с роли; для удобства в
  настройках пространства (вкладка «Общие») переключатель «Временные комнаты — могут создавать все
  участники», который ставит/снимает бит у базовой роли Member. Кастомные роли — через редактор ролей.
- Создатель временной комнаты имеет на ней права `MANAGE_ROOM` неявно (как автор личного
  представления доски в ADR-0042): переименовать, продлить, скопировать/отозвать ссылку, удалить.
  Реализация: `computePermissions` не трогаем — сервер при проверках `MANAGE_ROOM` на комнате с
  `expires_at` дополнительно пропускает `created_by == user`. Клиент — та же логика в
  `lib/permissions.ts` (`mayManageRoom(room, me)`).

### API (все — `internal/rooms`)
- `POST /api/workspaces/{id}/rooms/temp` (`CREATE_TEMP_ROOMS`) → `TempRoomResponse{room, invite_url, event}`.
  Тело: `name` (1–100), `ttl_seconds` ∈ [15 мин, 7 сут] (пресеты в UI: 1 ч · 3 ч · до конца дня ·
  1 день · 3 дня · 7 дней · «до даты»), `with_event bool`, `guests bool` (ссылка пускает гостей;
  **по умолчанию включено** — сценарий «клиент по ссылке»), `private bool` и `member_ids[]`
  (≤ 50) — видимость (ниже), `category_id` не принимается: временные комнаты всегда в
  виртуальной группе «Временные» внизу списка (см. UI). Атомарно в одной транзакции:
  1. комната (`position` = max+1, `created_by`, `expires_at = now + ttl`, `is_private`);
     приватная — `room_permissions` user-override `allow = VIEW_ROOM|CONNECT|SPEAK|VIDEO|STREAM|
     SEND_MESSAGES|ATTACH_FILES` создателю и каждому из `member_ids` (как ручная приватная комната
     сегодня — использовать ту же функцию, не дублировать биты);
  2. ссылка `room_invites` с `expires_at` комнаты, `allow_guests` по флагу, `allow_bits` = те же
     биты, `require_approval` NULL (наследует `rooms.guest_approval`, ADR-0040) — это и есть
     «ссылка сразу появляется»; **вход по ссылке участника пространства** в приватную комнату
     добавляет ему такой же user-override (проверить: сегодня `allow_bits` применяется к
     гостям; для участников — добавить, идемпотентно, `INSERT … ON CONFLICT DO NOTHING`);
  3. при `with_event` — событие календаря (ADR-0038) от имени создателя: `room_id`, начало сейчас
     (округлено вверх до 5 мин), конец = `expires_at`, участники — пока только создатель
     (добавить людей можно в диалоге события). Лимит: ≤ 20 живых временных комнат на пространство
     (409 `TEMP_ROOM_LIMIT`), ≤ 5 на пользователя.
- `PATCH /api/rooms/{id}` принимает `expires_at` (только для временных; продлить ≤ 7 сут от сейчас;
  `MANAGE_ROOM` или создатель). `null` не принимается — временная не становится постоянной (иначе
  это обход `MANAGE_ROOM`; сделать постоянной может `MANAGE_ROOM` через отдельный флаг `make_permanent`).
- `DELETE /api/rooms/{id}` для временной = архивация (как для обычной, если сегодня это архивация —
  проверить и не менять поведение постоянных комнат). Создатель может.
- `GET /api/workspaces/{id}/rooms?archived=1` (`MANAGE_ROOM`) — архив: `Room` с `archived_at`,
  `created_by`, `expires_at`, `message_count`. История архивной комнаты читается обычным
  `GET /api/rooms/{id}/messages` (`VIEW_ROOM`, по правам на момент чтения), запись/голос — 410 `ROOM_ARCHIVED`.

### Видимость
- **Публичная** (`private=false`, по умолчанию): видна и открыта всем участникам пространства по
  их обычным правам, как любая голосовая комната.
- **Приватная** (`private=true`): `is_private`, видят и входят только создатель, выбранные в
  диалоге люди (`member_ids`, можно добавить позже через «Доступ» комнаты — существующий диалог
  прав) и все, кто зашёл по ссылке (участники пространства и гости). ~~Администраторы пространства
  видят её как любую приватную комнату (ADR-0008).~~ Изменено [ADR-0078](0078-private-temp-rooms-hidden-from-admins.md): не видят ни админы, ни владелец. В списке у приватной — замок рядом с `Timer`,
  как у обычных приватных.
- Переключение видимости после создания — «Доступ» комнаты (`MANAGE_ROOM` или создатель):
  `PATCH /api/rooms/{id} {is_private}`; при снятии приватности user-override'ы остаются (безвредны).

### Истечение
- Свипер в `internal/rooms` раз в 30 с (как автоотклонение в ADR-0040, с Redis-локом на инстанс):
  `expires_at <= now AND archived_at IS NULL` → в транзакции `archived_at = now`, все ссылки комнаты
  `revoked_at = now`, событие календаря (если ещё активно и заканчивается позже) укорачивается до
  `now`; затем LiveKit `DeleteRoom` (участники выходят, клиент показывает тост «Комната закрыта») и
  `ROOM_DELETE` в шлюз пространства. Никаких новых типов событий: `ROOM_CREATE/UPDATE/DELETE`
  несут `Room.expires_at`.
- Предупреждение за 10 минут — на клиенте по `expires_at` (`useNow`, тик раз в 30 с только у
  строки комнаты и у островка звонка), без серверного события. В голосовой комнате островок
  показывает «⏱ 9 мин» и кнопку «Продлить» (если есть право).
- Ретенция архива: `TEMP_ROOM_RETENTION_DAYS` (по умолчанию 90) — свипер раз в час удаляет
  архивные временные комнаты старше срока вместе с сообщениями/вложениями (как удаление комнаты).
  Постоянные архивные комнаты не трогаем.

### UI (docs/09 #141)
- «+» в шапке колонки: пункт «Временная комната» (`CREATE_TEMP_ROOMS`), иконка `Timer`. Диалог:
  название (фокус, Enter создаёт), срок жизни (сегмент пресетов + «до даты» с датой/временем),
  видимость — сегмент «Все участники / Только выбранные» с полем людей (`PeopleBar`, как в
  фильтре календаря) во втором случае, переключатели «Пускать гостей по ссылке» (вкл.) и
  «Добавить встречу в календарь». После создания —
  та же карточка показывает ссылку с кнопкой «Скопировать» и «Войти» (в голос сразу), а комната
  уже в списке.
- Список комнат: виртуальная группа «Временные» под категориями (не категория в БД, не
  перетаскивается), сортировка по `expires_at`. **Особая иконка**: `Timer` вместо динамика, рядом
  с названием остаток «1 ч 20 м» (`tabular-nums`, secondary), меньше 10 мин — иконка и остаток
  цветом `attention` (оранжевый токен). Та же иконка у события в календаре и на карточке ссылки.
- Меню строки («…» и правый клик) у временной комнаты: «Скопировать ссылку» · «Продлить» (пресеты
  +1 ч / +1 день / до даты) · «Добавить встречу» (если ещё нет) · «Удалить комнату» (подтверждение:
  «Комната закроется для всех, история останется в архиве»). Обычные пункты меню комнаты — как у
  голосовой, по правам.
- Настройки пространства → «Комнаты» (или «Общие»): переключатель «Временные комнаты — могут
  создавать все участники»; ниже «Архив» — список архивных комнат (название, кто создал, когда
  закрыта, сообщений) с «Открыть историю» (чат только на чтение, плашка «Комната в архиве»).
- Тосты: «Комната закрыта» участникам при истечении; «Осталось 10 минут» — один раз, только тем,
  кто в голосе.

### Права и безопасность
- `CREATE_TEMP_ROOMS` не даёт `MANAGE_ROOM` вне своих временных комнат. Ссылка временной комнаты —
  обычная `room_invites` с `allow_bits` по политике ADR-0016 (гость: CONNECT|SPEAK|VIEW_ROOM|SEND).
  Гостевой вход по ссылке подчиняется `INVITE_GUESTS`? — нет: ссылка создаётся сервером от имени
  комнаты, но флаг `guests=true` в `POST …/rooms/temp` требует `INVITE_GUESTS` (ADR-0043) у
  создателя; без него ссылка только для участников пространства.
- Продление ограничено 7 сутками от «сейчас», архив читается только с `VIEW_ROOM` и `MANAGE_ROOM`
  на список. Боты: создание/продление через `botAllow` с тем же битом; свипер не зависит от клиентов.

## Последствия
- Миграция `00048`: `rooms.expires_at`, `rooms.created_by`, индекс `rooms_expires_idx (expires_at)
  WHERE expires_at IS NOT NULL AND archived_at IS NULL`; бит `CREATE_TEMP_ROOMS` существующим ролям Member.
- Клиент: строки временных комнат перерисовываются раз в 30 с (свой `useNow`), список — нет
  (правило ререндеров). Хранилище комнат уже получает `ROOM_DELETE` — архивная комната просто
  уходит из списка; открытый чат архивной комнаты закрывается с тостом.
- Отклонено: отдельный `type='temp'` (дублирует всю логику голосовой); серверный пуш «10 минут»
  (лишний тип события, клиент знает `expires_at`); полное удаление по истечении (владелец: история
  остаётся в архиве).

## Реализация сервера (30.09): уточнения и отклонения
- **Права создателя.** Одна проверка `rooms.MayManage(acc, user)` = `MANAGE_ROOM` в комнате **или**
  `acc.Creator(user)` (комната временная, `created_by == user`, пользователь — участник, не гость).
  Ей пользуются все проверки `MANAGE_ROOM` комнаты: `PATCH /api/rooms/{id}` (включая `expires_at`,
  `is_private`, медиа, `guest_approval`), `PUT …/permissions` (создатель разрешает, запрещает и снимает запреты только
  в пределах своих битов — правило `validateOverrides`; гостевой аккаунт личным allow — только с
  `INVITE_GUESTS`; `guest_approval` — тоже только с `INVITE_GUESTS`), `DELETE`, статус звонка. Ссылки: создатель
  `is_private`, медиа, `guest_approval`), `PUT …/permissions` (создатель разрешает только биты,
  которые есть у него самого — правило `validateOverrides`), `DELETE`, статус звонка. Ссылки: создатель
  управляет ссылками «только для участников» своей комнаты (как с `INVITE_MEMBERS`); гостевые —
  по-прежнему только с `INVITE_GUESTS`. На постоянной комнате `created_by` (теперь пишется и у обычных
  комнат) прав не даёт; `make_permanent` — только настоящий `MANAGE_ROOM`. Встречи комнаты в календаре
  (`canEdit`) неявного права не получают — создатель и так организатор своей встречи.
- **Ссылка.** `guests=false` делает ссылку `members_only` (ADR-0043), а не просто `allow_guests=false`:
  «только для участников пространства» — и гостевые аккаунты тоже не входят. `guests=true` требует
  `INVITE_GUESTS` на уровне пространства и подтверждённый email (как любая гостевая ссылка, ADR-0023).
  Биты ссылки и личных allow — `VIEW_ROOM | CONNECT | SPEAK | VIDEO | STREAM | SEND_MESSAGES | ATTACH_FILES`
  (§1 выше), но в пределах прав создателя в пространстве; `VIDEO` в `RoomInvite` отдельным флагом не
  показывается. Участник, вошедший по ссылке в приватную комнату, получает личный allow — это уже делал
  общий путь ссылок (`UpsertUserOverride` + `ROOM_PERMISSIONS_UPDATE`), проверено тестом.
- **`member_ids`**: только участники, не гости (гости входят по ссылке) — `422`. Приватность после создания
  (`is_private`) — только у временных; при включении создатель получает личный `VIEW_ROOM`, чтобы не
  потерять свою комнату.
- **Продление**: `expires_at` в (сейчас, сейчас + 7 сут], можно и сократить; ссылки комнаты, истекавшие
  вместе с ней, переносятся на новый срок. Встреча при продлении не двигается (бэклог).
- **Закрытие (удаление или истечение)**: встреча комнаты, которая идёт, заканчивается «сейчас»; ещё не
  начавшаяся — отменяется (письма, `EVENT_DELETE`); серии не трогаются. LiveKit-комнату закрывает
  существующая реакция `rtc` на `ROOM_DELETE`.
- **Архив**: читать можно `GET …/messages`, `…/messages/{id}`, `…/pins` и вложения; всё остальное по
  комнате — `410 ROOM_ARCHIVED` (только тем, у кого есть `VIEW_ROOM`; прочим — `404`). Архивные постоянные
  комнаты по-прежнему `404`. Список архива — `GET …/rooms?archived=1` (`MANAGE_ROOM` на уровне
  пространства, только комнаты с `VIEW_ROOM`, до 500 последних). Создание временной комнаты в
  приостановленном пространстве — `403 WORKSPACE_SUSPENDED`.
- **Боты** (`botAllow`): создают только с `guests=false` и без встречи (`403 BOT_NOT_ALLOWED`), продлевают
  и удаляют свои комнаты.

## Контракт для клиента
- `POST /api/workspaces/{id}/rooms/temp` `CreateTempRoomRequest{name, ttl_seconds 900..604800, with_event,
  guests? (по умолчанию true), private, member_ids ≤ 50}` → `201 TempRoomResponse{room, invite_url,
  invite_code, event?}`; следом всем, кто видит, `ROOM_CREATE` (и `EVENT_CREATE`). Ошибки: `403`
  (нет `CREATE_TEMP_ROOMS`; `guests` без `INVITE_GUESTS`), `403 EMAIL_NOT_VERIFIED`, `409 TEMP_ROOM_LIMIT`
  (`used`/`limit`, `reason: "PER_USER"` — личный лимит 5, без reason — лимит пространства 20), `422`.
  Переключатель `guests` показывать только при `INVITE_GUESTS` (иначе отправлять `guests: false`).
- `Room.expires_at` — признак временной комнаты; `Room.created_by`; в архивном списке ещё `archived_at`,
  `message_count`. `mayManageRoom(room, me)` = `MANAGE_ROOM` в комнате || (`expires_at` && `created_by ==
  me` && я не гость).
- `PATCH /api/rooms/{id}`: `expires_at` (продлить/сократить, ≤ 7 сут от сейчас), `make_permanent`
  (только `MANAGE_ROOM`), `is_private` (только временные); `ROOM_UPDATE` (при смене приватности ещё
  `ROOM_PERMISSIONS_UPDATE`, шлюз превращает их в `ROOM_CREATE`/`ROOM_DELETE` для тех, чья видимость
  изменилась).
- «Скопировать ссылку» — `GET /api/rooms/{id}/invites` (создатель видит ссылки «только для участников»,
  гостевые — при `INVITE_GUESTS`) → `<PUBLIC_APP_URL>/r/<code>`; ответ создания уже несёт `invite_url`.
- `DELETE /api/rooms/{id}` → `204`, всем `ROOM_DELETE` (как при истечении). Открытый чат такой комнаты
  получает `410 ROOM_ARCHIVED` на любую запись — показывать «Комната в архиве».
- Архив в настройках: `GET /api/workspaces/{id}/rooms?archived=1` → `ListRoomsResponse` (новые сверху);
  «Открыть историю» — обычный `GET /api/rooms/{id}/messages`.
- Право в редакторе ролей: `PERMISSION_CREATE_TEMP_ROOMS` (8388608), подпись `perm.CREATE_TEMP_ROOMS`
  уже в i18n; переключатель в настройках пространства = бит у встроенной роли `member`
  (`PATCH …/roles/{memberRoleId}`).
